## 本轮修掉的问题（都是彩排逼出来的）

1. **相机被别的进程占着**：现场复查时发现一个残留的 `camd.py` 进程拉着 ffmpeg 占住 `/dev/video1`，同时占着 8090 端口。表现是「服务正常启动、拍摄 0%% 成功」。已清掉；`tools/preflight.py` 现在会点名占用者。
2. **测试读得太早**：服务的 HTTP 端口比后台预热线程先就绪，导致「预热」一栏读到 None、并且第一张成片付了约 1.1 s 的冷启动成本。已加 `wait_preloaded()`。
3. **降级场景演得不真**：原来用「申请 99 个 AI 核线程」来模拟拿不到核，实测本板上照样能拿到 EP（会话不硬占核），于是这条检查是假绿。已改为真实可达的场景：让模型加载失败。
4. **16:9 伴随版静默丢失**：渲染时的一个参数不匹配让 `-wide.jpg` 写不出来，而写失败只打一行日志、不影响交付，所以没有任何检查会红。已修 bug 并补上专门的断言。
5. **50Hz 抗频闪没生效**：代码里定义了常量却从没设到 V4L2（真机读数是 60Hz），现场会在灯下出现横向滚动条纹。已改用 `v4l2-ctl` 设置并读回验证（2 → 1）。

## 补记 · 2026-09-16：取图入口从「编号」改成「令牌」

**为什么要改**：取图链接原来是 `/p/SM-2026-0001` 这种**连号编号**。局域网里没问题，
但 A 方案要把它挂到公网域名上 —— 谁都能从 0001 数到 9999，把全场照片拉走、
甚至删掉。

**改了什么**：每条记录拍摄时生成一个 **22 位随机令牌**（`secrets.token_urlsafe(16)`）。
`/p/<令牌>`、`/api/photo/<令牌>.jpg`、`/api/thumb/<令牌>.jpg`、`/api/qr/<令牌>.png`、
`/api/photo-meta/<令牌>.json`、`DELETE /api/photo/<令牌>` 全部认令牌；
**编号只在操作员面板和取图页上显示**，拿编号取图 / 删图一律 404。

**验证**（同一台真机，服务端与前端一起同步重启后）：

| 项 | 结果 |
|---|---|
| `tests/test_server.py` | **68 PASS / 0 FAIL / 1 SKIP**，连跑 3 轮无抖动 |
| `tests/e2e_test.py --mock --n 20` | 全过：成功率 20/20 · 中位 **3.56 s** · **1010 人/小时** · 推理中位 **187 ms** · 20/20 走 EP SpaceMIT |
| `tests/test_qr.py` / `test_worker.py` / `test_matte_policy.py` / `test_preview_hub.py` | 全部 exit 0 |
| 「编号不是入口」新断言 | 单测 5 条 + 彩排 4 条，全部 PASS |
| 取图页真机渲染 | mock 相机拍一张 → 用令牌取图 → 无头 chromium 截取图页：页面上显示编号 `SM-2026-0001`，而 URL 里是 22 位令牌 |

**顺带修掉的一个假红**：二维码解码断言偶发失败 —— cv2 的检测器在这张小码上
**约 2.5% 解不出来**（40 张实测 1 张），同一张图加白边或放大后重试必成功。
已改成带重试阶梯。**检测器的脾气不该变成彩排里的一条红。**

**本轮没复测的**：真实相机那几条（`tools/preflight.py` 3 项、`tests/test_camera*.py`）——
相机当时不在 USB 总线上（物理掉线），与本次改动无关。
