# 装置5 · 合规与现场文案

> 本文件是**待法务/品牌审核**的文案底稿，不是已审核通过的终稿。
> 所有对外可见文字都必须过审后再上物料；上表列出的每一项都要有审核人签字。

## 1. 为什么这个装置的合规不能省

装置的核心动作是**采集人脸**。人脸信息属于**敏感个人信息**，
在《个人信息保护法》下需要单独同意、明示目的、限制保存期限、提供删除途径。
参会者扫码取图后还会发到社交平台——这意味着数据会离开我方控制。

同时，物料里涉及 **RISC-V 商标**（RISC-V International 的注册商标）
与 **K3 die shot 素材**（需官方授权）。这两项都不是"应该没事"，是需要明确授权的。

## 2. 能力边界（对外口径必须统一）

这是整个装置**最重要的一句合规口径**：

> **本装置只做人像分割，不做人脸识别。**

区别在哪：

| 做 | 不做 |
|---|---|
| 把"人"这个目标从画面里分割出来 | 判断"这是谁" |
| 本地推理，数据不出设备 | 建立人脸特征库、比对、识别身份 |
| 依据提示词（person）做开放词汇分割 | 依据生物特征做身份认定 |

**所有对外材料、现场话术、媒体采访都必须守住这条线。**
一旦被说成"人脸识别拍照机"，性质完全不同。

## 8. 数据留存与删除

| 项 | 规定 | 实现 |
|---|---|---|
| 保存期限 | **7 天**（待确认，配置项 `retention_hours`） | 配置化，默认 168 小时 |
| 自助删除 | 参会者可在取图页一键删除 | ✅ 已实现 |
| 操作员删除 | 按编号删除 | ✅ 已实现 |
| 删除范围 | 原片 + 掩码 + 成片 + 缩略图，整目录移除 | ✅ 已实现（e2e 覆盖） |
| 删除记录 | 留痕备查（谁、何时、删了什么） | ✅ `events.jsonl` |
| 到期清理 | 有人负责执行 | ⛔ **当前无自动清理任务，需人工执行**，见下 |
| 收集最小化 | 不记 IP、不记 UA、不记人脸特征 | ✅ 取图计数只记次数与时间 |

> **缺口**：系统目前**没有自动到期清理**，只有配置项和提示。
> 现场结束必须有人按期限手动清理 `photos/` 目录并保留删除记录。
> 若要自动化，可加一个定时任务；但即使用人工，也必须明确"谁负责"。

## 9. 媒体与对外传播口径

**可以说**

- 「现场照片的算力来自 K3 的 RISC-V AI 核，本地推理，不联网」
- 「支持现场即拍即取，扫码保存」
- 「我们只做人像分割，不做人脸识别」
- 「三种赛博风格，提示词可实时切换」

**不要直接说**

- ❌「一键分享到小红书/朋友圈」（平台无此接口）
- ❌「影楼级抠像 / 精修证件照」（技术做不到）
- ❌「人脸识别拍照机」（合规红线）
- ❌「保证照片质量」——应以彩排实测为准
- ❌ 任何未实测的性能数字（装置本身的推理耗时以大屏读数为准）
