# 装置5 · 社交传播与「一键分享」的真实边界

> 需求原文：「支持现场即拍即传，照片自动添加 #SpacemiTDevCon 水印，可一键分享至小红书或朋友圈。」
>
> 这份文档把这句话逐条拆开，写明**哪些已实现、哪些部分实现、哪些做不到**。
> 不做的事就不写进对外材料——现场穿帮比不做更糟。

## 1. 逐条对照

| 需求 | 状态 | 实现位置 / 差距 |
|---|---|---|
| 现场即拍即传 | ✅ **已实现** | 拍完即出编号与二维码；局域网扫码即得，不依赖公网 |
| 照片自动添加 `#SpacemiTDevCon` 水印 | ⚠️ **只做了一半** | **成片图上没有水印**：现场明确要求"只把抠像贴到图上、不要加框加字"，`keyvisual.compose()` 现在不画任何文字。话题标签只在**取图页文案**里（`pick.js` 的 caption）。要"图上带标签"是另一个取舍，**待拍板** |
| 「SpacemiT DevCon 2026」Logo | ⚠️ **临时版** | 底图上的手绘锁定组 + 界面锁定组（`brand.py`）。官方矢量到位后替换一处即全局生效 |
| 一键**保存**到相册 | ✅ **能存原图** | 取图页「保存原图」下载成片；iOS 上要长按「存储到照片」。**四种预裁比例当前没有**（那是早期原型的），用户得自己裁 |
| 一键**复制**文案 | ✅ **已实现** | 文案含话题标签与编号。明文 HTTP 下 `navigator.clipboard` 不存在，走 `execCommand` 兜底 |
| 一键**唤起** App | ✅ 已实现（**只能到主页**） | `xhsdiscover://` / `weixin://`。发布页没有公开且稳定的 scheme，落到哪一页由 App 决定 |
| 一键**分享**（系统分享面板，**带图**） | ⚠️ **要 HTTPS** | `navigator.share({files})`：面板里直接有小红书 / 微信，点进去就是发布页。**明文 HTTP 的 IP 下这个 API 根本不存在**（实测，见 §3.1），所以要先挂公网域名（§3.5） |
| 一键**发布**到小红书 / 朋友圈 | ❌ **做不到** | 两个平台都没有对第三方开放的发布接口（§2） |

## 2. 为什么「一键发布」做不到（技术事实）

**小红书**：没有面向第三方的图片发布接口。开放平台的能力集中在账号授权、
数据看板、商品与笔记管理，**不含「代第三方发布图文」**。

**微信朋友圈**：微信只开放两种与分享有关的能力，两者都不满足需求：

| 能力 | 限制 | 能否发照片 |
|---|---|---|
| JS-SDK（`updateAppMessageShareData` / `updateTimelineShareData`） | 仅**微信内置浏览器** + **已认证公众号** + 域名备案 + 服务端签名 | ❌ 分享的是**链接卡片**，不是照片本体 |
| 小程序（`wx.shareFileMessage` 等） | 需用户主动触发，且有数量与类型限制 | ❌ 不能直发朋友圈 |

**结论**：需求里「一键分享至小红书或朋友圈」在平台层面不存在。
能做的极限是**把发布前的手工步骤压到最少**。

## 3. 现在这条链路实际长什么样

### 3.1 明文 HTTP 局域网（现场默认）

```
拍完 → 扫码打开取图页（http://192.0.2.10:8090/p/<令牌>，22 位随机串，不是编号）
  ├─ ① 保存原图              ← 下载成片
  ├─ ② 复制文案              ← execCommand 兜底；话题标签与编号已写好
  ├─ ③ 分享到小红书 / 朋友圈  ← navigator.share 不存在，退化成复制文案
  ├─ ④ 打开小红书 / 打开微信  ← scheme 唤起，只能到 App 主页
  └─ ⑤ 用户在 App 里选图 + 粘贴 + 发布
```

**实测**（2026-09-16，K3 上用无头浏览器打开真实取图页）：

```
origin=http://192.0.2.10:8090   isSecureContext=false
navigator.share=undefined   navigator.canShare=undefined   navigator.clipboard=undefined
document.execCommand=function
```

这不是"没实现"，是**浏览器不给**：Web Share 与 Async Clipboard 都只在安全上下文里
存在，而明文 HTTP 的 IP 地址永远不是安全上下文。
所以「分享」按钮不会假装成功 —— 它老老实实退到"复制文案 + 引导"。

### 3.2 挂公网 HTTPS 之后（推荐）

```
点「分享」→ 系统分享面板弹出（图已经带上了）
              ├─ 小红书  → 直接进发布页
              └─ 微信    → 好友 / 朋友圈
```

`navigator.share({ files: [图片] })` 是**唯一**能真正跳到发布页的通道。

它有三个好处：**不经过公众号、不经过 JS-SDK、不需要备案**（系统面板是操作系统在管，
小红书 / 微信只是注册了接收方）。代价是：必须是 HTTPS。

### 3.3 早期原型里那套（未随开源发布）

早期浅色版原型包含 `share.js`、四种预裁比例（1080×1440 / 1080×1080 / 1080×1920 /
含二维码的海报）与 `/api/wx-signature` 签名代理；这部分实现未随本仓库发布，
当前 `app/` 没有。本文档此前把它们写成了"已实现"，是错的，已改。

## 3.5 公网 HTTPS（A 方案：K3 走隧道，照片不出机）

**架构**：K3 主动拨出去连你的服务器（frp），服务器上**你现有的反代**（nginx /
宝塔）收 443，只放行取图相关的路径。**成片始终只存在 K3 本机** —— 7 天留存与删除
入口都不变，合规口径一个字不用改。

（2026-09-16 改动：这套服务端**不再自带 Caddy** —— 443、证书、续期全是你现有反代
的事，我们只加一段转发。理由：服务器上本来就有站点和证书，再装一个 Caddy 只会
去抢 443、还得跟现有站点共存。）

```
手机 ──https──▶ nginx（服务器 :443，你自己的证书）
                   │  只放行 /p/ · /api/photo/ · /api/photo-meta/ · 取图页那 6 个静态文件
                   ▼
              127.0.0.1:10111  ← frps（外网访问不到）
                   ▲
                   │ 隧道：K3 主动拨出 → 服务器 :7000
              K3 :8090（照片都在这里）
```

**部署**：自建反向代理 / 隧道环境，四个脚本 + frp 离线包 + `说明.txt`。
服务器上 `sudo bash server-install.sh <域名>`（**不装 web 服务器、不碰 443、全程离线**），
按 `说明.txt` 第二节把 location 白名单贴进你现有的站点；K3 上
`sudo bash k3-install.sh <域名> <密钥>`；然后在**操作员面板**填地址。

**地址填在哪儿**：操作员面板 →「取图页地址（分享用）」→ 保存。
改完之后**二维码缓存会被自动清掉**（二维码是按旧地址画好的 PNG，不清就会
"面板显示新域名、发出去的码指向旧地址"，且全程不报错）。
优先级：面板填的 > `BOOTH_PUBLIC_HOST` 环境变量 > 局域网 IP。面板上如实标来源。

**非备案域名会卡住什么**：
- **境内服务器**：未备案域名的 80/443 会被云厂商拦 —— 这种要用境外/香港机器；
- **微信 JS-SDK**（§4）：要求 JS 安全域名已完成 ICP 备案，非备案做不到 ——
  但我们不需要它了，系统分享面板已经覆盖，而且是发照片不是发链接卡片；
- **证书本身不受影响**：Let's Encrypt 免费 DV 证书随便签。

### ✅ 上公网之前**必须**补的两件事（2026-09-16 已修）

1. **取图入口不再连号**。每张照片拍摄时生成一个 **22 位随机令牌**
   （`store.Record.new_token()` = `secrets.token_urlsafe(16)`，128 位），
   `/p/<令牌>`、`/api/photo/<令牌>.jpg`、`/api/thumb/<令牌>.jpg`、
   `/api/qr/<令牌>.png`、`/api/photo-meta/<令牌>.json` 全部认令牌。
   **编号（`SM-2026-0001`…）只出现在操作员面板和取图页面上**；拿编号取图、
   缩略图、二维码、元信息，一律 404 —— 从 0001 数到 9999 已经拉不走照片。
2. **删除权跟着链接走**：`DELETE /api/photo/<令牌>`，令牌就是凭证。
   没有令牌就删不掉任何东西。（老记录根本没有令牌字段 → 一律查不到，
   失败方向是"打不开"而不是"泄漏"，这是刻意选的。）

已经钉进测试，不是"打算做"：

- `tests/test_server.py`：5 条「编号不是入口 / 编号不是删除凭证」；
  「返回取图令牌（随机串、不是编号）」；二维码解码改成核对编进去的是
  **令牌链接**；`/api/photo-meta/<令牌>` 成功 + 编号 404 + 乱码令牌 404。
- `tests/e2e_test.py`：4 条「编号取不到图」+「拿编号删不掉」。

（服务端反代那段**路径级**白名单仍然要做：`/operator`、`/stage`、`/api/state`、
`/api/operator/*`、**`/api/preview.mjpg`** 这些在公网上一律 404，静态文件要一个个列
而不是写成 `/static/`。令牌化是第二道 —— 它挡的是
"用合法路径数编号"。两道要同时在：白名单挡"没有这个页面"，
令牌挡"有这个页面但不是你的照片"。）

## 4. 微信内分享卡片（可选项，需提前准备；**非备案域名做不到**）

> 微信要求「JS 接口安全域名」已完成 ICP 备案。域名没备案这条就只能放弃 ——
> 而且即使配齐，分享出去的仍是**链接卡片不是照片**。有系统分享面板后不必再走这条。

若希望在**微信内置浏览器**打开取图页时，右上角「···」能分享一张好看的卡片，
需要以下条件，缺一不可：

| # | 条件 | 谁提供 |
|---|---|---|
| 1 | 已认证**服务号/订阅号**（拿到 AppID） | 品牌 / 市场 |
| 2 | 域名**备案**且配置为 JS 接口安全域名 | 品牌 + 运维 |
| 3 | 服务端**签名服务**（用 AppSecret 换 access_token → jsapi_ticket → 签名） | 开发 |
| 4 | 配置 `booth.config.json` 的 `wx_js_sdk.enabled / appid / sign_url` | 现场部署 |

**未配置时系统行为**：`/api/wx-signature` 返回 `available:false` 并给出原因，
前端**安静跳过**，不显示任何"分享到微信"的假按钮。这是刻意设计。

> ⚠️ 即使全部配齐，分享出去的仍是**链接卡片**，不是照片。
> 这一点必须写进对外口径，不能含糊。

## 5. 真正提高传播率的两个杠杆

「一键」不是关键——**没有接口**，再优化也到不了"一键"。
真正影响传播量的是这两件事，本方案都已实现：

**① 编号 = 社交货币。**
`#0471`「我是第 0471 位见证者」有收集感与在场感。
编号同时用于取图定位与删除请求，不是装饰。

**② 画面本身要值得拍。**
大屏上滚动的见证者名册、逐像素成形的人像掩码——这两样比成品图更容易被现场拍照发出去。
**这是装置从"拍照机"变成"可传播事件"的地方。**

## 6. 现场操作话术（给引导员）

> 「扫这个码，图就能存到手机里，文案也给你写好了 —— 复制粘贴就能发。
> 小红书和微信不让别的程序直接替你发，所以最后一下得你自己点。」

**不要说的话**：
- ❌「扫一下就能自动发到小红书」（做不到）
- ❌「一键分享到朋友圈」（做不到）
- ❌「我们帮你发」（涉及代发风险）

## 7. 拍立得的处理

需求物料清单里有「拍立得 1 台」。方案**没有取消它，而是限定它的角色**：

| 项 | 结论 |
|---|---|
| 作为**主交付** | ❌ 不可行。相纸单价高、单张出片 90 秒以上、有卡纸与耗材断供风险，会成为整条流水线的瓶颈 |
| 作为**限量体验** | ✅ 建议。前 N 名 / 集齐印章 / 嘉宾专享。现场有人值守换纸，不参与主流程计数 |
| 替代方案 | 热升华打印机（约 2 元/张、约 60 秒），成本与速度都优于拍立得，可作为限量档的主力 |
| 数字照片 | 人人可得的主交付（扫码取图，零边际成本） |
| 徽章贴纸 | 人人可得的实体（需求已列） |

**采购与 SOP 里都保留了拍立得这一行**，只是标注了它的正确用法。
如果坚持"人人都出拍立得"，需要把单工位吞吐目标从 100 人/小时下调到约 25 人/小时，
并单独报预算——这个取舍需要项目负责人拍板。
