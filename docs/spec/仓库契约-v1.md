## 3. 存储

- 根目录：`BOOTH_DATA`（booth_server.py:37），本地默认 `app/data/`，真机 `/opt/devcon/app/data`（systemd 49 行）。
- `app/store.py` `Store`：`root`、`retention_hours`（默认 **168 小时**，42）、`event_year`；初始化创建 `photos/`、`thumbs/`、`captures/`（46-47）；`qr/`、`masks/` 由 `Booth.__init__` 创建（booth_server.py:304-305）。
- 文件与格式：
  - `records.jsonl`：一行一条 `Record`（`asdict` JSON，追加写，105-108）；读取时忽略未知字段（126-140）。
  - `counter.json`：`{year,value}`，先写 `.tmp` 再 `replace` 原子替换（64-68）。
  - `photos/<编号>.jpg`（成片，`store.photo_path` 95-96）、`thumbs/<编号>.jpg`（缩略图 98-99）、`captures/<编号>.jpg`（原片 101-102）、`masks/<编号>.png` 与 `<编号>-alpha.png`（booth_server.py:904-907）、`qr/<令牌>.png`（1447）、宽版 `photos/<编号>-wide.jpg`（948-950）。
  - `settings.json`：操作员填写的取图地址（`SETTINGS_PATH` 44；读写 1117-1140，整份原子替换）。
  - `style-catalog.json`：风格目录，运行时位于 `BOOTH_DATA/style-catalog.json`（`StyleCatalog(self.store.root)`，303；`catalog_path` aigc_catalog.py:391-392）；仓库另存一份 `app/data/style-catalog.json`（4 款启用风格，含 `is_default`）。
- 编号：`SM-<year>-<NNNN>`，跨重启自增（70-74）；2026 年即 `SM-2026-NNNN`，**仅展示**。
- 取图令牌：`secrets.token_urlsafe(16)` → **22 字符**（80-83）；`by_token` 要求长度 ≥16 后逐条 `hmac.compare_digest`（85-93）；编号长度 12 <16 → 直接 404（测试断言见 `test_server.py:163-170`）。令牌在 `Booth._run` 抓帧**前**生成并写入作业快照（815-818、961）。
- 删除：删除照片/缩略图/原片（142-151），记录保留并追加 tombstone（152-155）；`by_token` 不跳过 tombstone，重复删除幂等（返回 `removed:false`）。
- 留存清理：`purge_expired()` 只按 photos 文件 mtime 判 168 小时（194-219）。
- 彩排清场：`reset_for_event()` 清 5 个目录文件、把 `records.jsonl` 归档为 `records.jsonl.bak-<时间戳>`、编号归零（158-192）。
- 真机数据保护：`deploy.sh` 同步前备份 `data/records.jsonl` 与 `data/counter.json`，且 rsync 永不删 `data/`（deploy/README 48-49、232 行）。
- **本轮契约**（已写入 02-spec）：新队列/作业状态只允许写 `BOOTH_DATA` 下的**新**文件/子目录（建议 `BOOTH_DATA/auto-flow/`），原子写、不得覆盖 `records.jsonl`/`counter.json`/既有照片/`settings.json`。

## 4. 同意令牌链

- 签发：`ConsentBook.grant(kind="photo")` → `uuid.uuid4().hex`（**32 位十六进制**，不是 22 位取图令牌），内存字典 `token→expires`，TTL `BOOTH_CONSENT_TTL` 默认 600s（booth_server.py:153-173）。
- 校验：`ConsentBook.check(token)` 精确匹配 + 过期即删（175-185）；`revoke_all` 在 `/api/operator/restore`、`/api/operator/reset` 调用（1064、1098）。
- 使用：`/api/capture` 只认 `X-Booth-Session` 头或 body `consent_token`（1361）；无效 403（1362-1365）；前端 `booth.js:99/259` 先 `POST /api/consent {agree:true,kind:"photo"}`，再在 `booth.js:285-298` 带 `X-Booth-Session` 调 `/api/capture`。
- 现状缺口（T-12/T-8 要补）：令牌不绑定任何主体/队列/作业，可被并发复用；`kind` 不做校验；无 `capture`/`external_processing` 区分；外置 AIGC 处理**没有独立同意**——只要 `AIGC_ENABLED=1` 且 `AIGC_BACKEND=public_api`，拍摄流程就会调网关（`_aigc_scene` 776-777、`aigc_client.enabled()` 22-26），页面只在文案上披露。
- 重启行为：同意令牌仅存内存，进程重启全部失效；这与“重启后必须重新同意”的新契约方向一致。

## 5. 操作员授权机制

**结论：现状没有任何授权机制。**

- `/operator` 页面对所有可达 8090 的客户端返回 200（1298-1299）；`/api/operator/*` 全部在 `do_GET`/`do_POST` 无任何身份或来源校验（1310-1313、1377-1412），包括 AIGC 目录编辑（含提示词）、USB 总线复位、purge/reset。
- 唯一的“门禁”是合规同意令牌，只保护 `/api/capture`（1360-1365），与运营路由无关。
- `BOOTH_HOST` 默认 `0.0.0.0`（1480），真机 systemd 也是 `0.0.0.0`——能否从公网/访客网段访问完全取决于现场网络与仓库外的隧道/代理配置。
- **未知 + 阻碍**：仓库内没有反向代理/隧道配置，无法证明 `/api/operator/*` 未暴露到公网。在 T-20/T-19 落实“仅回环或显式本地授权”前，禁止把这些路由当已受保护；任何依赖“操作员接口安全”的生产接线一律阻止。
