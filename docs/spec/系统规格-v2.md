## 1. Architecture（架构）

### 1.1 复用边界与证据

代码依据为 app/booth_server.py 的 Handler.do_GET/do_POST/do_DELETE、Booth.capture/_run、ConsentBook；app/camera.py 的 Camera 与 PreviewHub；app/infer_client.py 与 app/infer/worker.py 的 @@J 行协议；app/store.py 的 Record/Store；app/render/ 下 keyvisual/stylize/card/watermark/qr；app/static/js/ 的 booth/stage/operator/pick/net；app/tests/ 现有断言脚本。

- 真实 POST /api/capture 成功是 **202 + job + poll**，不是同步 200 + 二维码。GET /api/job/{job} 完成后给 token，再取二维码。保留此契约。
- 真实取图页是 /p/{token}、static/pick.html；新增 /photo/{token} 作为同一页面的兼容别名，不另造 photo.html。
- 当前预览参数代码默认 720p，但现场测量已采用预览=拍照=1920x1080；部署明确固定二者相同，12fps，MJPG，不调回 4K。
- measured facts：preview-photo-same-size 为 3.81s / 46% 单核；pixel-cost-is-linear 为约 19ms/MP；camera-selfheal-8s 为约 8s；card-canvas-1600x900 为画布 1600x900、人像窗约 278x357；photo-entry-is-token 为 128bit 随机取图令牌。
- 知识库有旧事实：perf-yoloe-cpu=0.30s、perf-ep-speedup=1.9、req-consent-gate=400 已被后续实测或代码取代。本规格采用 1157ms CPU 对照、403 门禁；n/s 档 0.22/0.54s 不与其他量化样例 31.8ms 混用。
- README/注册表另记窗口约 411x526、MODNet 512² 约 1340ms，与简报 278x357、256² 266ms 不同。不得默改运行参数或声称旧 3.81s 已覆盖任何组合。T-13 记录实际模型 SHA256、尺寸、窗口、配置并复测；成本规划仍按简报小窗和 1080p，不放大素材、不改底图坐标。合成坐标只读 keyvisual.window_rect()。
- app/queue.py 会遮蔽 Python 标准库 queue（booth_server.py 已 import queue）；新增文件命名为 app/reservation_queue.py。

### 1.3 三条验收边界

**L0** 是既有实拍成片，拍摄、推理降级、合成、存储、二维码、现场局域网取图全不依赖 WAN 或 AIGC；完成 L0 后工位立即接下一位。AIGC job 不持有 capture lock，不占 AI 核、不等待供应商健康检查，也不延迟队列完成。AIGC 失败不扣除 L0 成功。相机无法取到真人帧或磁盘不可写时不能伪造成功，保留原号、恢复后重拍；MOCK 成片不能计入真人交付。

“断网可用 100%”按 PRD 已明示的 **L0 无公网依赖**执行：WAN 拔线、场内 AP/LAN/K3 仍供电可达时 100/100 获取 L0。公网 API 风格图此时不可用；LAN GPU 仅在已安装并健康时可继续。手机仅有蜂窝网络、AP 客户端隔离或 LAN 全毁时，无法从 K3 下载，不能把它算离线验收通过。现场提供独立 AP、固定 LAN 地址、Wi-Fi 加入二维码及 LAN 取图二维码；网络全毁时工作人员保号恢复，硬件容灾/纸质打印不在现有设备能力内。

公网仍**仅承载取图业务**，不开放排队、同意、拍摄、预览、stage/operator/state。排队二维码默认 LAN；手机须先加入现场 Wi-Fi。蜂窝直达公网排队与当前白名单边界不兼容，列入 open_questions，未批准不开放。取图页中的风格请求属于领取增强，仅携照片 token 可用。

## 3. Data models（数据模型）

以下为新增字段契约。str 是 Unicode 字符串；时间持久化为 UTC ISO8601，过程计时用 monotonic。可选字段明确默认值；JSON 无 NaN/Infinity。

### 3.1 Consent / StationSession

ConsentBook 内存记录：token:str（uuid4 hex，32 字符）、session_id:str（32 字符）、ticket:int|null、granted_at:str、expires_at:str、agree:true、guardian_confirmed:bool=false、minor:bool=false、notice_version:str="v2"、consumed:bool=false。TTL=600s；minor=true 且 guardian_confirmed!=true 不签发。签发新工位同意、恢复、切换参会者、重启均使原武装失效。一个 session 对应当前唯一参会者；队列票号不构成同意。

CaptureSession：session_id、consent_token（只在内存和授权操作响应）、state:unarmed|armed|qualifying|countdown|capturing|completed、ready:bool、lease_expires_mono:float、armed_until_mono:float、last_frame_seq:int、job:str|null、ticket:int|null、blocked_reason:str|null。最大 1 个活跃会话。页面每秒心跳、3s 无心跳撤防；arm 最长 90s 且不得长于 consent TTL。成功取快门权即消耗同意，重试须重新同意；请求幂等重放仅返回旧 job，不再次曝光。

### 3.2 PoseSample（临时，不落盘）

frame_seq:int、frame_at_mono:float、width:int、height:int、person_count:int、box:[float,float,float,float]|null（原始非镜像图像归一化 xyxy，0..1）、keypoints:dict[str,[float,float,float]]（x,y,score）、ep:bool、ep_threads:int、infer_ms:float、total_ms:float。实际模型张量名称/形状在 T-13 验证后由 decoder 固化，不把候选 COCO 17 输出当成已知 EP 输出。对外无原始 keypoints，仅状态/debug。内存历史最多 3s，撤防清空。

### 3.3 Photo / StyleJob

Record 保留现有 id、token、created_at、prompt、ep、infer_ms、person_count、degraded、seed、card、style、event、extra。新增 extra.schema_version=2、expires_at:str、generation_epoch:int=0、deleted_at:str|null、background:str。不新增个人姓名、手机号、微信字段。内部文件名可用 id，HTTP 永远用 token。旧无 token 的记录保持不可领取，不为其生成可枚举入口。

StyleJob：job_id:str（32 hex）、record_id:str、epoch:int、idempotency_key:str（16..64 ASCII）、styles:list[str]（1..5 去重）、catalog_version:str、backend:disabled|lan_gpu|public_api、status:queued|running|completed|failed|cancelled、created_at:str、deadline_at:str、external_consent_at:str、external_notice_version:str、results:list[StyleResult]、error:str|null、provider_request_id:str|null、cost_cny:float|null。photo status 为 idle|queued|running|completed|partial|failed；cancelled 由删除变成 404。StyleResult：name:str、url:str（本站 token URL）、width:1600、height:900；内部另含 style_id、文件名、provider 耗时/费用，不向公网返回供应商链接/标识。

每个 (record_id, epoch, catalog_version, style_id) 最多提交一次，重复 key 同载荷返回原 job，不同载荷 409。单照片最多一个生成批次，无自动付费重试；补生成须后续另定预算策略。删除先提升 epoch 并标 tombstone，再清缓存/源图/成片/风格/掩码/QR/job 私密数据；迟到结果写入前持锁复验 epoch 与到期，永远不能复活照片。provider 请求只能带临时 request_id，不能带照片 token、队列票或昵称。

存储：原 records.jsonl/counter.json 保留；data/styles/{record_id}/{style_id}.jpg；data/style-jobs.json 原子替换、仅存 job 元数据；原片只复用 data/captures/，不额外复制全分辨率源；若保存外部输入临时文件，deadline/取消即删且受相同 168h 上限。匿名聚合 metrics.json 不含可关联身份字段。

### 3.4 Queue

data/queue.json：schema_version:int=1、next_ticket:int（从 1 自增，重启不倒退）、revision:int、current_ticket:int|null、entries:list[QueueEntry]。
QueueEntry：ticket:int、queue_token_hash:str（SHA256；原始 token=secrets.token_urlsafe(16)，仅首次响应）、nickname:str|null（选填，去两端空格，1..24 字符）、show_nickname:bool=false、status:waiting|called|serving|done|skipped|cancelled、joined_at:str、called_at:str|null、arrived_at:str|null、completed_at:str|null、notice_version:int、ack_at:str|null、expires_at:str。
nickname 空值显示“访客 #123”。大屏仅在 show_nickname=true 时公开昵称，否则显示访客号；个人票响应可显示自己昵称。队列 token 只管理该票，不能取照片；photo token 不能管理队列；序号均不是授权凭证。队列到照片的内部关联仅由受信工位维护，不通过票号公开照片链接。

取号用 Idempotency-Key，服务端持久化其 hash 与票映射；客户端预生成并保存随机 queue_token，经请求提交，保证首响应丢失可凭同 token 重试，不持久化原 token。200 回同票、201 新票。取消清昵称与令牌 hash，保留匿名号段防倒号。终态昵称 24h 内清除，活票最长 24h，所有可关联记录最迟 168h 清除；票号计数可保留。每次修改 RLock + 临时文件 fsync + os.replace；非法/损坏 JSON 启动拒绝取新号并报警，不能悄悄清零；保留最近一次有效原子快照。

## 4. Interfaces / API（接口契约）

### 4.1 通用规则

现有路由保留；下文明确标“新增/扩展”的才改变。HTTP JSON 使用 application/json，响应统一 no-store，Referrer-Policy:no-referrer。新请求最大 16KiB，未知字段拒绝 400；图片由服务器读取，不接受公网任意 URL/任意路径。路径 token 必须匹配 [A-Za-z0-9_-]{22}，serial 访问一律 404。style_id 只允许当前目录项，不作为任意文件名拼接。

错误形状 E = {"ok":false,"error":str,"detail":str}；新增接口全部采用 E。共有 400 bad_request、401 operator_required、403 consent_required/forbidden_origin/queue_token_required、404 gone/not_found、409 conflict、413 body_too_large、429 rate_limited、503 unavailable。409/429 不消耗同意；业务拒绝应可重试但不能自动重签 consent。HTTP 429 带 Retry-After:5。旧接口原有细小错误形状保持兼容，见 4.2。

LAN 并不等于操作员身份：所有 /api/operator/* 和工位武装操作要求 X-Booth-Operator（本机配置 256bit 随机 secret），浏览器由值守输入后仅 sessionStorage；无默认弱口令。精确 Origin 白名单，不开放 CORS，不信任客户端 X-Forwarded-For。缺 token 的 capture 优先返回 403（即使 force=true），满足硬红线；校验通过后才校验操作员 force 权限。普通手动 capture 可凭同意令牌，不要求操作员 secret。公网网关不透传任何工位路由。

### 4.2 既有拍摄与领取接口（核对过代码）

- POST /api/consent，原请求 {"agree":true,"kind":"photo"}；agree=false 原返回 200 {"ok":false,"error":"consent_declined"}。扩展可选 ticket:int|null、minor:bool=false、guardian_confirmed:bool=false、notice_version:"v2"。仅现场拍摄位签发，ticket 须是 serving 票，否则 409 ticket_not_serving。200 返回 {"ok":true,"token":str,"expires_in":600,"kind":"photo","purpose":str,"retention":str,"version":int,"at":str,"session_id":str}。未成年人未获监护同意返回 403 guardian_required；kind!=photo 为 400。不把“取号”或操作员口头确认当自动签发。
- POST /api/capture，header X-Booth-Session 或 body.consent_token（均给且不一致 400）。已有字段 style:str|null、background:str|null、name:str=""、handle:str=""、seed:int=7、mnemonic:str|null。本轮新 UI 移除 name/handle 收集；兼容接收但不记录/不展示旧客户端传来的 name/handle。新增 session_id:str?、trigger:"manual"|"auto"="manual"、request_id:str?（32 hex）。auto 必须匹配会话、武装、当前 pose/倒计时；外部不能仅传 auto 绕过控制器。
  - 有效请求返回 202 {"ok":true,"job":str,"style":str,"record_id":str|null,"poll":"/api/job/{job}"}，record_id 仍可能是 null。
  - 无/过期/撤销/已消费同意 403 {"ok":false,"error":"consent_required","detail":"拍摄前需要先获得参会者的单独同意"}；合法幂等重放同一 request_id 仅返回旧 job，不重新拍摄。
  - 忙 409 capture_busy；auto 判据失效 409 pose_not_ready；真实帧不可用 503 camera_unavailable。服务端锁内在实际 camera.snapshot 前再次 check consent，消除排队/线程间过期竞态。
  - POST /api/capture?force=true：仅操作员+有效同意可跳过姿态，仍为 202；force 只能是 true/false，否则 400。日志只记 trigger/force/job/耗时，不记录 IP/token。
- GET /api/job/{job}，仅 LAN，200 返回现有 Job.snapshot：
  {"job":str,"stage":"queued|capturing|inferring|rendering|storing|done|failed","ok":bool|null,"error":str|null,"record_id":str|null,"token":str|null,"style":str,"degraded":bool,"degraded_reason":str|null,"ep":bool,"ep_threads":int|null,"infer_ms":float|null,"total_ms":float|null,"person_count":int,"mask_applied":bool,"steps":list[{"key":str,"label":str,"ms":float|null,"detail":str,"at":float}],"elapsed_ms":float}。
  新增可选 qr_url、lan_photo_url、public_photo_url，只有 done 才给；未知 job 404 {"ok":false,"error":"unknown_job"}。
- GET /p/{token} 仍返回 pick.html；新增 GET /photo/{token} 返回同页。页面壳可以 200，底层数据严格校验 token。
- GET /api/photo/{token}.jpg、/api/thumb/{token}.jpg、/api/qr/{token}.png：200 对应 JPEG/JPEG/PNG，否则 404 E(gone)。扩展 QR 参数 scope=public|lan，默认 public 兼容；缓存键含 scope+link_base+token，LAN 不被公网域名覆盖。
- GET /api/photo-meta/{token}.json：200 {"ok":true,"id":str,"ep":bool,"degraded":bool,"style":str,"at":str}，旧无效 token 返回 404 null；保持旧消费者兼容，不返回 token 清单。
- DELETE /api/photo/{token}：200 {"ok":true,"id":str,"removed":bool}；无效/已删 404 E(gone)。本轮扩展为删除全部派生版本并撤销生成任务。若物理擦除尚待重试，先使所有读取 404，返回 202 {"ok":true,"id":str,"removed":false,"status":"deletion_pending"}，操作员可见重试；不能假报已擦除。

原 /、/stage、/operator、/api/build、/api/state、/api/overlay.json、/api/health、/api/operator/config、restore/purge/reset/usb-reset 的现有字段保留；新增操作员认证。/api/mask/{id}.png 历史编号入口改为 /api/mask/{token}.png，由 store.by_token 校验，stage 的 mask_url 统一更新；旧编号掩码也 404，避免“图片一律 token”留例外。不在公网开放掩码。

### 4.3 姿态 / 自动拍摄（新增，LAN）

### 4.4 排队接口（新增，全部 LAN）

## 5. Error handling（错误与状态机）

### 5.1 姿态探针与 go/no-go

T-13 是第一个任务：候选优先轻量 YOLO-Pose INT8，固定输入先试 320²，必要时 640²；导出/量化在开发机做，K3 仅 EP 编译和推理。记录模型来源/许可证、校准集授权、sha256、opset、张量签名、量化配方、编译工具/版本及生成 .so 文件证据；Session 列出 SpaceMIT 并不证明每个节点真在 AI 核，必须结合编译/分图日志、运行计时和 CPU 对照。没有 .so 证据不能通过 FR-1。

硬门槛：pose 请求/实际槽数均 <=2，所有 EP 会话常驻总数 <=8；seg=4、det=2、pose=2，clip/MODNet 固定 CPU；每会话重试阶梯只向下，不能再用现有 8,4,2,1 跳到更高档。既有 worker 会话生命周期占槽，不能用“调用没重叠”掩盖超额。未获槽立即禁用 pose，不挤走 seg/det。不要跨活进程 force_release TCM。

10 次预热+至少 200 帧测量，pose inference P95<=300ms，端到端含预处理 P95<=400ms，目标 2.5Hz（400ms 周期）、仅最新一帧、队列长度 1；完整 1080p 12fps 双预览+拍摄对照连续 10min，无泄漏/崩溃/复位增加；总进程 RSS<=4GiB 且增量<=512MiB；预览均值>=11.5fps、P95 帧间隔<=125ms；CPU 姿态增量<=0.5 单核、预览+pose 空闲采样合计<=1.0 单核。至少 20 次 L0 对照 P50<=4.2s（3.81s 基线约+10%）；最终长测 P0 仍依第 7 节。

Go 只代表试验门槛通过，不代表误触发率已通过；另以 >=100 次独立真人准备/未准备场景验收 <=2%。缺模型/硬件/编译失败/超过任一预算明确 no-go 或 unavailable，保存原因，不能 SKIP 当 PASS。CPU MoveNet/其他 CPU pose 只作为探针对照，同样测上述预算；即使通过也不满足 FR-1“AI 核”要求，默认不启用，须显式变更验收。no-go 路径交付“有同意的手动拍摄”，FR-1 与自动能力标未达标，其他流可以继续。

### 5.2 自动触发

无有效同意为 unarmed；同意 + 现场“我已准备好” + 新鲜 pose + 当前工位独占后 armed。人体数量必须恰好 1；镜像只显示，不参与坐标判断。bbox 高度占画面 0.45..0.90，四边不越 0.02..0.98；中心 |dx|、|dy|<=0.10。肩线角绝对值 <5°；双肩置信度>=0.60、肩间距/bbox宽>=0.35；鼻点仅作为全身 pose 的一个点、要求 score>=0.60、落在双肩中点横向±0.15肩宽内且位于肩线上方。不使用独立人脸检测、眼耳细化、embedding、脸部对齐、身份比对或跨人跟踪。

“facing_front”是以上**身体/头部朝向代理**，不是识别正脸的事实；水平肩线不能区分背对/转头，遮挡、不确定、鼻点缺失全部 false，探针必须含背对/转头负例。若全身 pose 仍无法把正面与背面对照分开，判 no-go，不谎称 FR-1 已满足。

稳定窗口 >=1.5s，>=5 个不同 seq 有效样本、相邻 gap<=0.50s；窗口中心最大两两位移/画面对角线 <0.03，并且尺度变化<=5%。所有条件连续成立后进入 3.0s 可取消倒计时，每个新样本复验；任意多人/缺失/超阈值/陈旧帧/同意过期/切人/心跳失效立即清空稳定历史并撤销倒计时。最近样本 age<=500ms，快门前再检查一次；倒计时不受 reduced-motion 缩短。拿到 capture lock 后消耗令牌、状态 capturing，完成/失败均 unarmed，下一人必须新同意，不循环拍。单纯离开浏览器页不能保留武装。

### 5.3 AIGC 运行方式与降级

部署形态为**可插拔单后端，本项目后端已定为自有 OpenAI 兼容网关的 `public_api`**（模型 `gpt-image-1`，端点/密钥由操作员界面配置，见 §4.7）。LAN GPU 保留为可选实现，不再是默认路径。不暗中跨网转发，用户同意的是当前告知中指明的处理方。默认 disabled，预算为 0。

**网关契约已实测（2026-09-18，开发机）**：`POST {base}/v1/images/edits`（multipart：`model`/`prompt`/`size`/`n`/`image`）与 `POST {base}/v1/images/generations`（JSON）均 HTTP 200，图片在 `data[0].b64_json`（该网关不给 url 形式）；`size` 至少支持 `1024x1024` 与 `1024x1536`；计费按 token（图生图输入约 832 图片 token + 文本 token，输出 158~196 图片 token），网关不返回价格元数据，单张成本需按账户单价折算。延迟实测：文生图 1024² **13.5s**、图生图 1024² **29.3s**、图生图 1024x1536 **45.1s**；因此**默认 1024x1024**（构图由本机按人像窗 cover 裁切），竖版仅在审美确有收益且延迟可接受时启用。真人照片的保真度尚未验证，列入 open_questions，不能据合成图样张宣称已通过。风格是同一授权实拍的生成式人像重绘（服饰/画风/背景），不只是替换底板，不用 FaceID/InstantID/人脸识别 embeddings；是否像本人由本人/人工验收，不自动比对。

首发目录只定义 `main-film-chip` 一项：抠像后把单人像放到纯平中性灰上传件，调用外置图像编辑只重绘人像为成熟的手绘动画电影风，再做二次抠像并与配对手绘芯片底板合成。每人默认选择这一项，也可以只取 L0；以后新增风格仍是一项一次外置生成，不是免费批量产物。上传件最长边<=1536、去 EXIF、JPEG<=512KiB；上传前必须复用 `person_count==1` 判据，画面含第二人时该张不提供增强入口，除非操作员显式确认。返回静态图最长边<=2048且解码<=4MP、传输<=4MiB，去 EXIF并重编码。姓名、机构、队列票、照片token与准确大会文字都不得进入请求体。

**风格图主流径：抠像 → 人像 AIGC 化 → 二次抠像 → 合成（2026-09-18 改定）**

现场反馈：抠像贴底板的成片「人像与背景完全突兀」。**根因不是抠像本身，而是「实拍人像的锐利边缘与真实光照」和「风格化背景」不是同一套视觉语言**。因此**保留抠像**，但让人像也过一遍 AIGC：

1. **抠像**：MODNet 逐像素软 alpha（发丝保留），只用拍摄位的实拍帧做一次。
2. **灰底中转**：把人像合成到中性灰 `#7F7F7F`（无渐变、无阴影、无物件）作为 AIGC 输入 —— 灰底比绿幕更不容易被模型误当作"要替换的背景"。
3. **人像风格化**：`/v1/images/edits` **只重绘人像**。prompt 强约束：背景必须保持纯平灰、不得加渐变/物件/投影；保持人物位置、比例、轮廓与发型；五官可辨；不得增删身体部位。
4. **二次抠像**：对风格化结果再跑一次 MODNet → 风格化 alpha（本地 CPU，亚秒级）。
5. **合成**：风格化人像 + 底板 + **接触阴影**（alpha 大半径模糊 + 偏移 + 压暗约 55%）+ **轮廓光**（alpha 边缘环 × 品牌色，约 55%）→ 人像「站进」画面而不是贴上去。
6. **底板默认由代码渲染**（暗调渐变 + 细网格 + 品牌色）：零成本、零失败、品牌完全可控、与卡片/界面同源；只有需要沉浸式场景时才改为 AIGC 生成背景（多一次调用、多 20~40s）。
7. **版式框架**（编号徽章、二维码、水印、品牌条）仍由代码渲染，不经模型。

**为什么这样就不突兀**：边缘不再是「照片的锐利边」，而是「被同一套笔触画过的边」；再叠加与背景共享的接触阴影与轮廓光，人物与背景共享同一套光照语言。
对比样张：`samples/aigc-probe/cut-stylize/00-对比-现在vs抠像后风格化.png`（左＝现在，中＝三渲二，右＝手绘）。

**整图重绘（保留为可选「场景款」）**：输入实拍原帧，人像与背景一次生成，风格最统一，连展会现场都能保留可辨
（见 `samples/aigc-probe/whole-frame/`）；代价是每张背景都不同、品牌一致性差、且丢掉「我确实在大会现场」的证明力。
作为独立风格选项可用，**不作默认**。

**基础框架分两层，风格完全交给 AIGC**：
- *构图框架（固定，由 prompt 模板前缀 + 后处理裁切保证）*：半身、人物居中偏下、头顶留白 ≥6%、两侧 ≥5%、预留 logo 区、单一人物。
- *版式框架（由代码渲染，不经模型）*：卡片底、编号徽章、二维码、品牌条、水印 —— 品牌一致性不依赖模型。

**风格 = 一条可编辑的 prompt 模板**：操作员界面可改、可复制新建、可启停，改完热加载（见 §4.7 与 T-38）。要什么风格改 prompt 即可，不用改代码。
**多版产出**：一次请求可含多个风格（每风格一张），也可同风格多变体；默认 1 版、可加选。
**命名合规**：风格名与 prompt **不得出现第三方工作室/作者名称**（吉卜力/Studio Ghibli、迪士尼、皮克斯等），一律描述性命名（如「日式手绘动画电影风」「三渲二赛璐璐」）。

**实测（2026-09-18）**：本地 MODNet(onnxruntime CPU) 抠像与二次抠像各亚秒级；人像风格化 1024×1536 —— 三渲二 **23.6s**、日式手绘 **20.0s**（158~343 图片输出 token）。
**成本与整图重绘相同（都只有一次生成调用）**，背景走代码渲染则零额外成本。
整图重绘另一组实测：4 款风格 1024×1536 单张 22.1~42.7s、343 token，均无贴图感。

**风格体系设计（提案，待品牌与负责人定稿）**

1. **双轨定位**：同一装置服务两种目的，风格按「像本人」的程度分档，UI 必须标注相似度。
   - *证件档*（相似度：高）：只换底色/光/肤色质感，几乎不重画五官 —— 能当**头像、简历/社交资料照**用。
   - *纪念档*（相似度：中）：换背景与光效、可选换服装质感 —— 发朋友圈用。
   - *艺术档*（相似度：艺术化）：插画/水墨/像素化，**必须提前告知「艺术加工、可能不像本人」**，并始终保留 L0 原片兜底。
2. **风格 = 参考图 + 固定模板，不是一句自由 prompt**：每款风格存 `{id, name, tagline, similarity, ref_image, prompt_template, size}`，
   全部版本化进 `catalog_version`。只靠文字描述会让同一款风格在 10 个人身上漂移成 10 个样子，品牌方和参会者都不会接受。
3. **何时生成（关键取舍）**：默认**拍完先给 L0（约 4s）+ 二维码**，风格图在**参会者扫码并选定风格后**才提交 ——
   不替没选的人花钱，也让 29s 的等待发生在「他已经拿到 L0、正在保存/发圈」的时间里。
   进一步优化：在取号/填资料环节就让人预选风格，拍完即刻提交，等人走到取图页时图可能已经好了。
4. **默认 1 张、按需加选**：实测 29.3s/张、并发 2 → 上限约 245 张/h。默认 1 张时 100 人/h 余量充足；
   默认 3 张会超出约 22%。想多要就自己再点 —— 成本与等待由选择决定，而不是默认替所有人买单。
5. **允许「离场后取」**：生成结果挂同一 token（留存 168h），取图页本来就在公网。
   现场等不到的人回家照样能取，这反而是最强的二次传播点，不要当失败路径处理。
6. **纯图、不加框不加字**（沿用现场已确认的偏好）：风格图就是生成结果本身；框、字、编号只留在 L0 卡片上。
7. **输出质检**：固定 prompt 含「no text, no logo, no watermark, single person」；落盘后做一次轻量检查
   （出现明显文字/多脸则丢弃该张，可选重试一次）—— 宁可少给一张，不能给出错字乱码图。
8. **品牌语汇**：风格名要有梗、可被参会者复述（如「K3 霓虹」「指令集水墨」「RISC-V 复古未来」），
   因为名字会被写进朋友圈文案；视觉必须落在暗调 + 科技语汇里，与现有 L0 卡片体系同源。

**用途边界（必须写进物料与取图页）**

本装置交付的是**大会纪念创作**，L0 与全部风格图**均不作为证件材料使用**，物料、取图页脚注与 AIGC 告知里各写一行（例如「本图为 SpacemiT DevCon 2026 纪念创作，不作为证件材料」）。理由三条，缺一不可：
1. 法定证件照有硬规格（尺寸、背景色、头部占比、是否露耳、能否美颜），各受理机构自行规定，我们无法覆盖；
2. 生成式重绘会改动五官细节（痣、双眼皮、脸型比例），**改动过的脸本身就不符合证件照要求**；
3. 部分机构明确不接受 AI 生成或 AI 修改的人像作为证件材料。

命名与文案口径：风格目录里的「素底证件」对外统一叫 **「证件风」**，避免暗示法定证件照；`similarity` 标签仍标「高」。

**风格图交付两份（建议）**

现在 §5.3 把生成图合成进 1600x900 横向卡片，人像窗只有约 278x357~411x526 px——
**这个尺寸打印 2 寸照片（300dpi 约需 413x579）是不够的，当头像也要裁**。建议同一份生成结果交付两个产物，**不增加生成成本**，只多一次渲染与少量带宽：

| 产物 | 用途 | 规格 |
|---|---|---|
| `portrait` 竖版纯图 | 头像、打印、自己再创作 | 生成原尺寸（1024x1024 或 1024x1536），去 EXIF，不加框不加字 |
| `card` 品牌卡片 | 分享、存档、现场展示 | 沿用 1600x900 卡片体系 |

取图页默认展示 `card`（有品牌感、适合发圈），并提供「竖版原图」的独立下载入口（懒加载，不并入批量下载）。若品牌方希望更强可用性，可将 `portrait` 尺寸提到 1536（每张延迟与 token 上升，需重测）。

**风格选择器设计（提案）**

1. **入口与时机**：主入口在取图页 `/p/{token}`（扫码后）——他刚拿到 L0，正是选风格的时刻；次入口是取号/填资料页的**可选预选**，预选后拍完即可提交，等人走到取图页时图可能已经好了。
2. **卡片用什么图**：每款风格一张卡，展示**官方示范图**（同一示范人物、同一构图、品牌统一素材）＋ `风格名` ＋ 一句话卖点 ＋ `相似度标签（高 / 中 / 艺术化）` ＋ `约 30 秒`。
   - **不用参会者自己的照片做预览**：那等于每次预览都生成一次（约 29s 且要花钱），不可行。
   - 官方示范图必须是有授权的素材，随 `catalog_version` 版本化。
3. **选择规则**：默认勾选 1 款「本期主推」；可多选，上限 `AIGC_MAX_PER_PHOTO`（默认 5）。按钮文案写清代价——「生成 2 张 · 约 30 秒」，不用「提交」这类模糊词。额度或预算到顶时按钮置灰并给出诚实文案，不静默失败。
4. **生成中**：显示进度，并提示「可以先把原片保存/分享，风格图稍后回来取」；重复点击不得造成二次付费（幂等键）。
5. **完成后**：逐张展示、点击/长按保存。**不做「一键全部下载」**——每人 5 张 × 1~3MB 会打爆公网带宽，只对当前图懒加载（与 §7 带宽预算一致）。
6. **相似度告知**：艺术档在提交前必须弹一次确认：「艺术加工，可能不像本人；原片始终保留」。
7. **目录管理**：`data/style-catalog.json`（版本号 + 每款 StyleSpec），操作员页可见版本与启用状态，品牌定稿后冻结；热加载 <5s，校验失败保留旧目录。
8. **移动端与断网**：竖屏单列卡片、大触控区、无 npm/CDN、`prefers-reduced-motion` 生效；离网时明确提示「风格图需要联网，原片不受影响」。

降级链：L0 总是先完成 → 后端可用且授权则尝试生成 → 多风格部分完成保留结果 → 拒绝/断网/过期/超预算/队列满则 L0-only。目录占位图不能冒充生成结果。
单图截止<=60s，批次从接收算也<=60s（排队占用预算）；全局并发=2、最多 10 个等待 style 子任务；FIFO 按参会者轮转，单人先一张再余项。预计排队+执行超过剩余 deadline 则直接拒绝新增子任务。满额即 fallback，不无限排队。
连接超时 3s，读等待受总 deadline 截断；无自动付费重试，网络重连不重复提交；连续 3 个网络/5xx 错误熔断 60s，半开单请求。服务重启将 running 标 failed/restart，不自动重复付费；queued 若过期丢弃，未到期也需幂等确定后才能恢复。生成耗时不计入工位时长。

### 5.4 排队 / 提醒

前台每 5s poll，stage 每 3s poll；visibilitychange 回前台立即刷新，失败退避 5/10/20/30s，重新可达恢复 5s，显示“连接中，现场叫号为准”，不能把旧号伪装实时。setInterval 有 in-flight guard，防慢响应叠加；style 每 2s，终态/60s 停止。
called+未见过 notice_version 才提醒一次：页面明显提示 + alert；用户主动“启用声音”后 WebAudio 短音，支持时 navigator.vibrate([200,100,200])，不支持静默回退到视觉。后台浏览器被挂起、锁屏、iOS 不支持震动、内嵌浏览器策略均可能不通知。无 App/公众号/SMS/push 服务，**没有可靠强提醒承诺**。现场大屏数字叫号+工作人员喊号/确认到场是兜底；离场无法保证追达。

T-15 先用静态页面/人工叫号验证 iOS Safari、Android Chrome、微信内置浏览器（至少 iOS/Android 各一台）的 LAN HTTP、前台、后台 2min、锁屏 2min、声音授权/拒绝、弱网、WAN 断线。前台可见变化 P95<=6s、大屏<=4s；>=20 次模拟叫号，确认收到>=19/20 仅作探针，正式覆盖率样本>=100 且>=95%（所有已取号者为分母）。背景挂起不算故障掩盖，弱提醒接受度未拍板则不得宣称 FR-7 业务验收已完成。

## 6. Security（安全与合规）

1. consent 与 ready 分开，排队、看到镜头、姿势达标、操作员点击均不替代参会者单独同意。旧前端 403 后自动 ensureConsent 的逻辑必须移除，提示重新阅读并主动勾选。minor 需监护人单独确认；现场灯光提示继续保留。
2. 手机取号与实体人不做人脸关联；到位时由工作人员核对号码、现场同意，单人站位。仅依持有远处队列 token 不能武装摄像头。
3. 照片 token 最少 128bit，queue token 与 consent token 域隔离。禁止 serial 获取照片、风格、缩略图、QR、元信息、删除及掩码。请求 token 仅服务器能力凭证，不包含姓名。静态目录使用 pathlib.is_relative_to/父路径边界防穿越，不沿用字符串前缀判断作为新增接口守卫。
4. 原片、成片、生成结果、外置输入、队列关联、包含 token 的 job/备份均受 168h 最大留存；到期访问立即 404，后台每 60s 擦除，启动先清理。数据目录权限最小化；队列昵称终态后 24h 清理；日志只聚合，BOOTH_ACCESS_LOG=0。nginx/Cloudflare/frp/供应商日志也关闭 IP 与 URL token 记录；验证不能只看 Python log_message。
5. 单张删除入口继承为删除该照片所有风格、取消外部任务、清理缓存。不能删除供应商训练副本的服务不启用；要求 no-training、无持久留存或可核验删除及最长 168h 合同上限。远端取消失败持续重试/告警，界面说明“本站已删除，外部清理处理中”，不作虚假承诺。
6. 外置上传需第二个独立勾选，明确处理方、地点/网络、用途、保留、删除、风格可能改动肖像。供应商不得采用人脸识别保真技术。预算、数据出场地授权未明确前 disabled。
7. 公网白名单精确到 method/path：GET /p/{token}、/photo/{token}、现有领取静态依赖、/api/photo-meta/{token}.json、/api/photo/{token}.jpg、/api/thumb/{token}.jpg、/api/qr/{token}.png、/api/photo/{token}/status、/api/photo/{token}/style/{style_id}.jpg、/api/aigc/styles；POST /api/aigc/generate；DELETE /api/photo/{token}。所有其余路径 404，尤其 /api/preview.mjpg 永不放行，不用 /api/* 前缀许可。不开放 /stage 来做云叫号。
8. 公网/API body<=16KiB，端点固定、允许域名白名单、TLS 校验不关闭；密钥环境/受限文件注入不进仓库、不进 /api/state；外端返回图由受限适配器读取，不允许任意 URL 重定向/访问内网元数据；LAN endpoint 仅人工配置的固定地址。
9. 限流不依赖 IP：生成每 photo 一批/最多5图+全局并发；取号凭 token 与幂等键、全局每秒5次、活票100；HTTP 短请求并发64，排队请求单连接超时5s。公网服务保留原 50Mbps；LAN 页面不能带公网预览引用。
10. RISC-V 注册商标声明与 die shot 官方授权沿用，品牌风格上线前确认；不把生成模型能力宣称为 K3 算力成果。

## 12. 实体打印与装板（新增，2026-09-18）

现场方案：**Canon SELPHY CP1500 + 亚克力板固定，横版竖版都出**。打印机已到场，尚未连接 K3；本节先冻结接入边界，真实队列、纸张裁切和产能仍由 T-39 验收。

### 12.1 纸张与像素（6 寸照片纸）
| 产物 | 纸与精度 | 输出像素 | 生成尺寸 |
|---|---|---|---|
| 竖版 | 100×148mm @300dpi | **1181×1748** | 1536×2048（3:4，裁到 1.48:1 再缩） |
| 横版 | 148×100mm @300dpi | **1748×1181** | 2048×1536（4:3，裁到 1.48:1 再缩） |

- 若实际是 2×3 英寸 ZINK 口袋机（50×76mm，313×400dpi），所需仅约 626×938，1024×1536 就够，按机器定。
- 网关已确认支持 1536×2048 与 2048×2048；实测 1536×2048 与 2048×1536 各约 **25s**、**556 图片输出 token**
  （对比 1024² 的 196 token，**贵约 2.8 倍**）→ 打印档成本要单列预算，不能沿用 1024² 的单价。
- 构图：竖版头顶留 ≥6% 高度、两侧 ≥5% 宽度；横版主体放一侧 1/3，另一侧 2/3 留给品牌区与二维码。
- **既有的 1600×900（16:9）横版卡片不适配 6 寸纸（1.48:1）**，打印必须另出版面，不能直接缩。

### 12.2 安全边与反光
- 打印机有 2–3mm 裁切/白边误差 → **3mm 安全区（@300dpi = 36px）内不得放重要元素**（人脸、logo、二维码）。
- 暗调影像 + 亮面亚克力会眩光：**用磨砂/哑光亚克力，或照片覆哑膜**，先做一张样板验证再批量采购。
- 装板方式（双面胶/卡槽）、板厚（2–3mm）、是否留白边，由物料侧定稿；软件只输出 12.1 的两种版面文件。

### 12.3 驱动通道（CP1500，先验再开关）
- CP1500 的首选通道是**同一局域网内的 IPP Everywhere**：固定打印机 IP，K3 用 CUPS `-m everywhere` 建队列，目标 URI 为 `ipp://<打印机IP>/ipp/print`。
- USB 备用通道是 `ipp-usb`，设备 ID 为 `04a9:3302`；禁止使用裸 `usb://` 队列。Debian/Bianbu 自带的旧版 `ipp-usb 0.9.23` 存在 CP1500 双接口问题，目标版本至少为 `0.9.24`，现场优先使用更新版本。
- 资料与未连接前的操作步骤见 `docs/佳能CP1500-K3接入与打印SOP.md`。T-39 仍必须在真实设备上确认：① IPP 或 USB 哪条通道稳定；② CP1500 自报纸型；③ 首张和连续出片是否正确。
- 软件侧不得把“CUPS 已提交”当成“纸已出”；验收前保持打印开关关闭，电子版始终是主交付。

### 12.4 吞吐账（与既有验收线冲突，必须拍板）
- 单张打印 40–60s（热升华约 60s）+ 人工贴板装亚克力 20–30s → **单工位 ≈60–80s/人 ≈ 45–60 人/小时**。
- 横竖各打一张 → 打印时间翻倍 → **约 25–30 人/小时**。
- 既有验收线是 **≥100 人/小时**，两者不可能同时成立。二选一：
  - **(a) 打印限量**（前 N 名/集章/嘉宾/付费），主线仍是扫码取电子版 → 保留 100 人/小时；
  - **(b) 人人打印且横竖都出** → 吞吐验收线改为约 **25–30 人/小时**，并配 1 名专职值守换纸装板。
- 耗材成本另计（6 寸相纸含色带约 2 元/张量级，横竖两张即翻倍），需进预算表。
- 这与现场文档既有结论一致（`docs/01-物料BOM与搭建.md` §4：不要用拍立得、热升华约 60s/张、必须限量/专人值守）。

### 12.5 打印失败兜底
- 卡纸/缺纸/断连：**不阻塞主流程**。数字版始终可交付；打印故障时明确提示「稍后凭二维码取电子版」，
  并退回人工排队打印，不静默吞掉。

| L3 | 文字块总宽 ≤ **68%W**，超宽**自动降字号**，不溢出、不换行、不缩排 | 竖版画布窄，照搬横版字号必压主体 |
| L4 | 文字块右边界必须 **< 主元素左边界** | 实测模型会把主元素画到文字上 |
| L5 | 主元素（芯片/吉祥物）只允许在右上角并被上/右边缘裁切；横版进一步收紧到 **x≥84%W、y≤32%H** | 不写死这条约束时，模型把芯片放画面中央并压住文字（`_sheet.png` → `_sheet2.png` 两轮失败） |
| L6 | 下 **74%H** 为纯净区，只放人像与阴影；背景资产在此区不得有道具/面板/边框 | 人像合成区 |
| L7 | **中英文文字一律代码渲染**；背景 prompt 必须含 NO text/letters/numbers/logo/watermark | 模型画中文必出乱码错字（用户 prompt 里的 "Characters complete and correct" 不可靠） |
| L8 | 可读性用**文字带局部渐变蒙版**（暗底压暗、亮底提亮；峰值约 40% 不透明度、带宽 24%H、高斯 46px），不做整屏压暗 | 整屏 scrim 会把背景压平、失去质感 |
| L9 | 主元素只用品牌色：琥珀 #FFA53B / 青柠 #B0E237 / 霓虹青 #35E0FF / 品红 #FF3DBE | 与官网元素一致 |

### 13.2 归一化版面规格（按画布 W/H 分数取值，渲染器据此计算）
| 项 | 屏幕竖版 2:3 | 屏幕横版 16:9 | 打印竖版 1181×1748 | 打印横版 1748×1181 |
|---|---|---|---|---|
| 画布 | 1024×1536（生成用 1536×2048） | 1600×900（生成用 2048×1536 再**居中裁**到 16:9） | 1181×1748 | 1748×1181 |
| 文字左边界 | 7.5%W | **55.0%W** | 7.5%W | **55.0%W** |
| 第 1 行基线 | **8.8%H**（字顶约 4%H） | **13.0%H**（字顶约 6%H） | 同竖版等比 | 同横版等比 |
| 第 1 行 script 字号 | 自动 fit ≤68%W（实测 **3.84%H**） | 自动 fit ≤**46%W**（实测 **6.67%H**） | 同竖版等比放大 | 同横版等比放大 |
| 第 2 行 sans | 1.28%H、字距 0.20em、≤66%W | **2.10%H**、字距 0.20em、≤44%W | 同竖版 | 同横版 |
| 第 3 行中文 | 2.05%H，缩进 +5.2%W | **3.00%H**，缩进 +3.0%W | 同竖版 | 同横版 |
| 主元素 | 右上 x74–100% / y0–18% | AIGC 右上 **x84–100% / y0–32%**，主体被上/右边缘裁切 | 同竖版 | 同横版 |
| 人像 | 头顶 **36%H**、水平居中、主体高 78%H（底部出血） | **水平中心 27%W、头顶 6%H、主体高 106%H**（底部出血） | 同竖版，重要元素避开 3mm 安全区 | 同横版 |

- **文字锁定组必须贴近卡片上方安全边**：竖版首行基线 8.8%H、横版 13.0%H；品牌字顶分别约 4%H / 6%H。主题、姓名、机构与头衔从此向下排列，为可选个人信息预留连续空间，不能把品牌组放到画面中腰。
- **竖版不能照搬横版**：横版是「左人右文 + 最右上 AIGC 元素」；竖版画布窄、人像居中，直接搬横版规格会文字压脸。竖版仍采用「顶部文字带 + 右上角主元素 + 下部人像」三段式。
- **横版不是竖版的等比放大**：人像固定在左侧，中心约 **27%W**、占用约 x4–48%；文字从 **55%W** 起排在右栏；AIGC 主元素仅在最右上角 x84–100%，不能进入人像区，也不能形成文字背后的面板或边框。
- **人像必须同时受高度与宽度约束**：`scale = min(高度上限/人像高, 宽度上限/人像宽)`，竖版宽上限 88%W、横版 44%W。否则头肩特写（宽高比 >0.8 的素材）会撑满整幅。
- **人像落位用 `max(头顶下限, 出血锚点 - 人像高)`，不能用 `min`**：写反了人像会浮在画面中间、头顶比规格高一截，直接压到文字带（实测踩坑，已修）。头顶下限：竖版 36%H、横版 6%H；出血锚点：底部 102%H。
- 网关**不支持 16:9 直出**（支持 1024²、1024×1536、1536×2048、2048²、2048×1536）→ 横版底图用 2048×1536（4:3）生成后**居中裁到 16:9**，主元素坐标按裁切后的帧重新计算。
- 打印档按 §12.1 像素出图，字号按上表比例等比放大，**不重新设计版面**。

### 14.1 个人信息栏（印在成片上）
**四个字段，前三个全部选填**；不填的字段**整行不渲染**，不留空行、不留占位符。

| 字段 | 上限 | 字号（竖版 / 横版） | 颜色 |
|---|---|---|---|
| 姓名或昵称 `name` | 8 个中文字符或 16 个西文字符 | **6.80%H / 10.50%H**，加粗并自动缩小 | 主字色，整张卡的文字主视觉 |
| 公司或学校 `org` | 20 字符 | 1.65%H / 2.50%H | 次级字色 |
| 一句话头衔 `tag` | 16 字符 | 1.40%H / 2.10%H | 次级字色（更弱） |
| 编号 `serial` | 系统生成 `SM-2026-XXXX`，仅作取图/内部元数据 | 不渲染到成片 | 不适用 |

- **位置与层级**：竖版沿用顶部信息带；横版整组从 55%W 起放在右栏。品牌行基线为竖版 6.4%H / 横版 8.8%H；`开发者见证者` 基线 11.2%H / 15.4%H；品牌色竖线从 14.5%H–25.8%H / 18.8%H–40.5%H；姓名基线 22.5%H / 31.5%H；机构 27.6%H / 38.2%H；固定标语 `开源造物 · 从芯开始` 基线 30.7%H / 42.8%H。姓名不填时，`开发者见证者` 自动放大补位。编号只进入取图令牌和内部元数据，不绘制底部编号条；`#SpacemiTDevCon` 只进入分享文案。
- **字体口径**：不再使用手写连笔字体。品牌行使用清洁的无衬线体并带官方图形标记；姓名使用粗体中文无衬线；机构与一句话身份使用常规中文无衬线。字距保持字体默认值，不做负字距。
- **自动适配**：`name` 超宽先**逐级降字号**；降到下限仍超宽则**尾部省略号截断**，并在填写页即时提示——**不换行、不缩排、不溢出**。
- **硬约束**（进 T-42 断言）：
  1. 竖版信息块右边界 ≤68%W；横版信息块从 55%W 起，常规文案控制在 82%W 前，长姓名可降字号但不得超过 95.5%W；
  2. 竖版信息块底边必须**高于人像头顶**；横版信息块与左侧人像分栏，不得相交；
  3. 打印档信息块不得进入 3mm 安全区；
  4. 不填的字段不产生任何像素（渲染前后像素差为 0）。
- **竖版构图随之调整**：人像头顶由 28.5%H 下移到 **36%H**、主体高 78%H，让出信息带——否则姓名会压在头发上（实测 `samples/info-bar/` 前一轮）。
- **不加额外水印**：沿用用户结论（背景本身已有元素）。信息条是「让人愿意晒」的东西，不是水印。
- **隐私（PII 红线）**：`name`/`org`/`tag` 是个人信息，**只存本机 `BOOTH_DATA`，随同一 token 生命周期（168h）一起删除**；不写日志、不进 state；**绝不写进 AIGC prompt**（不得把真实姓名送去外部生成）；取图页只显示本人 token 对应的信息，不提供他人信息接口；三项全部选填，页面明写「三项都可以不填」。

### 14.2 用户界面（参与者侧）
两套界面：**现场大屏（stage）** 与 **手机（pick / queue）**。不新造色，全部复用 `app/static/css/tokens.css`（spacemit.com 官方暗色令牌：底 `#000`、面 `#1E1E20`、描边 `#262626`、品牌绿 `#9FEF00`）。「官方暗色主题」本身就是 iOS 深色的语言，所以「用 spacemit.com 元素」与「iOS 25 feel」是同一个方向。

**大屏两态**（落点 T-32）：
1. **待机**：品牌 lockup + 「赛博开发者证件照」+ 三步说明 + 大二维码 + 当前叫号 + 底部合规一行。
2. **拍摄引导**：实时预览（叠虚线取景框）+ **3·2·1 大字倒计时** + 右侧状态卡（人像就位 / 光线正常 / 保持不动）+ 底部提示条。取景框与「人像就位」来自**姿态/分割模型的几何判断**，**不做人脸识别**。

**手机五屏**（一条流水线，不跳步；落点 T-29 + T-31）：
1. **欢迎**：一句话讲清玩法 + 三步清单 + 底部合规两行。
2. **填信息**：三个选填输入 + 字数计数 + 「名字会印在这里」小预览。
3. **选风格**：5 个方向 + 「不选也可以（用原片）」，选中态品牌绿描边 + 对勾。
4. **生成中**：进度环 + 预计时间 + 号码/风格/版面三行 + 「可以先逛展」提示；关掉页面不影响。
5. **取图**：竖版/横版切换 + 保存/复制文案 + 现成分享文案（含 `#SpacemiTDevCon`）+ 底部「本图为纪念创作，不作为证件材料使用」。

- **文案红线**：产品名沿用「赛博开发者证件照」，但**每一屏都必须带那句免责声明**；不写「可用于证件办理」。
- **不承诺自动发帖**：受平台限制，微信/小红书只能「复制文案 + 跳转过去手动粘贴」，界面如实这么写，不给「一键分享到小红书」这种做不到的按钮。
- **空态与降级**：AIGC 关闭/失败时，选风格屏隐藏风格网格只留「用原片」，生成中屏直接进取图屏，界面不出现死胡同。

1. **单一主方向**：参与者默认且当前唯一可见的 AIGC 风格为 `main-film-chip / 手绘芯片主方向`。背景使用 `app/assets/bg/devcon2026-keyvisual-film.png`；旧深/浅底板保留作内部候选，不删除、不随机展示。
2. **成片链路**：L0 仍是本地抠像基础成片；增强链路为 `MODNet 抠像 → 灰底上传件 → AIGC 只风格化人像 → 二次抠像 → 与配对手绘芯片底板合成`。AIGC 失败、断网、预算关闭都只影响增强图，不影响 L0。
3. **文字边界**：AIGC 输入禁止文字、数字、logo；大会字标、英文副线、`开源造物 · 从芯开始` 与选填个人信息全部由本地资产/代码输出，个人信息不进入 prompt。
4. **提示词目录**：`data/style-catalog.json` 为运行期目录，`app/data/style-catalog.json` 为首装种子；每项字段为 `id/title/description/prompt/model/sizes/enabled/is_default/revision/history`。当前实现 API：
   - `GET /api/operator/aigc/styles`：完整操作员目录，不含密钥；
   - `POST /api/operator/aigc/styles`：新增一项，或提交 `styles` 全量原子替换；
   - `POST /api/operator/aigc/styles/{id}`：编辑/启停；
   - `POST /api/operator/aigc/styles/{id}/rollback`：恢复上一有效版本；
   - `GET /api/aigc/styles`：仅返回启用项的 `id/title/description/sizes`，不返回 prompt。
5. **目录校验**：ID 为小写字母/数字/短横线；名称、说明、prompt、model、sizes 有长度/格式边界；至少一项启用；只允许一个默认项；禁止第三方工作室/作者名称；写入采用临时文件 + `os.replace`，失败不覆盖旧目录。
6. **横竖与打印**：横版主构图沿用当前已确认方向（小人像靠左下、芯片在右）；竖版与两种打印尺寸由 T-42/T-40 在同一视觉语言下单独排版，不允许简单拉伸横版。
7. **当前完成度**：主底板、种子目录、目录服务、操作台编辑/新增/启停/回滚 UI 已在本地实现；外部生成配置、StyleEngine、领取页生成流程、队列、pose、打印仍按计划任务推进，不能视为已上线。
