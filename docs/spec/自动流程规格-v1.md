我先检查仓库现有服务、路由、测试与规划目录，确保技术契约复用实际命名，并避免覆盖既有规划。随后新增 `02-spec.md`，对未验证能力明确设为 gated 或 unknown。## Architecture
- 现场服务继续由 `app/booth_server.py` 提供，监听端口 `8090`。本轮扩展沿用现有页面和 API；不引入 npm、CDN、外部字体或新服务进程。
- 浏览器页面使用原生 HTML/CSS/JS，通过同源 HTTP API 与现场服务通信。大屏 `/stage` 展示系统和队列状态；拍摄位 `/` 展示风格轮播和当前拍摄状态；`/operator` 展示运行状态和允许的人工恢复操作；`/p/<token>` 提供取图操作。
- 服务端新增队列、预约状态机、手势检测适配器、作业编排、打印适配器。它们作为 Python 模块运行在 `booth_server.py` 进程内；不得将 `cv2` 与 `spacemit_ort` 放入同一进程。涉及 `spacemit_ort` 的进程必须先导入 `onnxruntime`。
- 队列提交产生预约记录。到号并由参与者点击开始后，服务端检查相机、有效同意令牌和手势能力状态。只有手势能力经 K3 验证且配置启用时，连续稳定的 OK 手势才可触发倒计时和现有 `POST /api/capture` 流程。
- 相机目前存在已确认的物理链路故障。启动自检必须能报告无帧状态；不得将设备枚举成功当作相机可用。相机未通过取帧自检时，禁止自动拍摄并显示清楚的故障状态。
- 原始图像进入风格化作业。AIGC 外发只允许发送图像和必要风格参数；在参与者单独同意外置处理前不得发起请求。AIGC 不可用或失败时，作业回退至 L0 结果。
- 取图入口只使用 22 位随机令牌。`SM-YYYY-NNNN` 仅供显示，任何页面/API 均不得以此编号授权访问。
- 打印通过适配器隔离设备协议。协议和设备未验证时，打印请求返回不可用状态，不得伪报成功；可支持的人工协助流程须由产品决策后启用。

## Data models
以下字段构成本轮 API 契约。持久化格式须兼容现有存储；具体文件后端不在此处假定。

```ts
type QueueStatus =
  | "queued"
  | "called"
  | "ready"
  | "capturing"
  | "processing"
  | "ready_for_pickup"
  | "expired"
  | "cancelled"
  | "failed";

type ConsentRecord = {
  consent_id: string;
  purpose: "capture" | "external_processing";
  granted: boolean;
  created_at: string; // ISO 8601 UTC
  queue_id?: string;
  job_id?: string;
};

type QueueEntry = {
  queue_id: string; // opaque random identifier; not a photo access token
  request_id: string; // client-generated idempotency key
  status: QueueStatus;
  style_id: string;
  created_at: string;
  updated_at: string;
  called_at?: string;
  start_deadline?: string;
  started_at?: string;
  expired_at?: string;
  consent_id?: string;
  display_number?: string; // SM-YYYY-NNNN; display only
};

type QueueSubmission = {
  request_id: string;
  style_id: string;
  optional_fields?: Record<string, string>;
  capture_consent_id: string;
};

type GestureResult = {
  available: boolean;
  gesture: "ok" | "none" | "unknown";
  confidence?: number;
  stable_frames: number;
  person_count?: number;
  in_frame?: boolean;
  observed_at: string;
  reason?: string;
};

type CaptureJob = {
  job_id: string;
  queue_id: string;
  status: "created" | "countdown" | "capturing" | "processing" | "completed" | "failed";
  capture_consent_id: string;
  external_processing_consent_id?: string;
  style_id: string;
  created_at: string;
  updated_at: string;
  fallback: "none" | "L0";
  error_code?: string;
  photo_token?: string; // present only when photo is ready
};

type PhotoRecord = {
  photo_token: string; // exactly 22 random URL-safe characters
  job_id: string;
  created_at: string;
  status: "available" | "deleted";
  variant: "L0" | "styled";
  display_number?: string; // never accepted as an access credential
};

type ComponentHealth = {
  status: "ok" | "degraded" | "unavailable" | "disabled";
  checked_at: string;
  reason?: string;
};

type SystemHealth = {
  camera: ComponentHealth;
  gesture: ComponentHealth;
  queue: ComponentHealth;
  storage: ComponentHealth;
  aigc: ComponentHealth;
  printer: ComponentHealth;
};

type PrintJob = {
  print_job_id: string;
  photo_token: string;
  status: "unavailable" | "queued" | "submitted" | "completed" | "failed";
  created_at: string;
  updated_at: string;
  error_code?: string;
};
```

- `optional_fields` 的允许字段、长度、存储期限和是否持久化均须由隐私决策确定；未配置字段不得收集。
- `request_id` 用于提交幂等，不得作为取图令牌或公开访问凭据。
- `photo_token` 由安全随机源生成，长度固定为 22；不得从编号、作业 ID 或个人信息推导。

Additional route rules:

- `POST /api/capture` remains the existing capture contract. Missing or invalid capture consent returns `403`; no queue or gesture feature may bypass it.
- 令牌路径的现有形状就是 `/api/photo/<token>.jpg`、`/api/thumb/<token>.jpg`、`/api/qr/<token>.png`、`/api/photo-meta/<token>.json` 与 `DELETE /api/photo/<token>`；直接沿用，不得改名。`/api/mask/<name>.png` 虽存在但未做令牌校验（已知缺陷，见上），生产接线前必须整改或仅限回环。
- Do not expose the internal gesture ingestion route to the LAN/browser. If the selected IPC mechanism does not use HTTP, omit this route.
- `GET /api/state` and `/api/overlay.json` must not expose consent values, optional personal fields, photo tokens, or full queue identifiers.
- `GET /api/health` is diagnostic, not an authorization mechanism.
- 队列访问私有性：`/api/queue/*` 面向前场参与者的手机浏览器（局域网可达），只允许凭不可猜测的 `queue_id` 读取单条记录；不得新增“列出全部队列”的公开接口；`/api/state`、`/api/overlay.json`、`/api/build` 只暴露脱敏聚合，不得包含完整 `queue_id`、令牌、同意值或可选个人信息。
- 仅回环或显式本地授权的入口：内部手势摄入（`POST /api/job/<id>/gesture`，若采用 HTTP）、测试夹具服务 `app/tests/run_auto_flow_fixture_server.py`（绑定 `127.0.0.1:18090`）、操作员/运维路由 `/api/operator/*`。现有 `/api/operator/*` **无任何鉴权**；在 T-20/T-19 落实限制前不得视为生产安全。
- 同意绑定：`POST /api/queue/<queue_id>/start` 与 `POST /api/capture` 必须校验同一个 `capture_consent_id` 与队列条目的绑定；`external_processing_consent_id` 不得替代拍摄同意，反之亦然。现状同意令牌是全局集合、无主体绑定（`ConsentBook` 153-196），绑定校验是 T-12/T-8 的新增实现要求。

## Error handling
| Code | HTTP | Meaning | Policy |
|---|---:|---|---|
| `INVALID_REQUEST` | 400 | Malformed JSON, missing required field, or invalid type | Reject without state change |
| `INVALID_TOKEN` | 404 | Token is malformed or is a display number | Do not reveal token validity details |
| `CONSENT_REQUIRED` | 403 | Required consent missing, invalid, or revoked | Do not capture or send image externally |
| `STYLE_NOT_FOUND` | 404 | Style ID absent from catalog | Reject submission |
| `IDEMPOTENCY_CONFLICT` | 409 | Same idempotency key used with a different request payload | Reject; preserve original record |
| `QUEUE_FULL` | 429 | Configured queue capacity reached | Show a retry message; do not silently drop |
| `QUEUE_EXPIRED` | 409 | Start deadline passed | Mark expired; require a new submission |
| `NOT_CALLED` | 409 | Start requested before this entry is called | Reject state transition |
| `CAMERA_UNAVAILABLE` | 503 | Camera health check cannot obtain a frame | Disable capture; show operator diagnosis |
| `GESTURE_DISABLED` | 409 | Gesture model unavailable, unvalidated, or disabled | Do not auto-trigger; remain in safe waiting/fallback state |
| `CAPTURE_FAILED` | 503 | Capture failed after authorization | Mark job failed; do not claim a photo exists |
| `AIGC_FAILED` | 502 | Gateway rejected or failed processing | Record failure and use L0 when source image is valid |
| `AIGC_TIMEOUT` | 504 | Gateway exceeded configured timeout | Stop retries for the job; use L0 |
| `PHOTO_NOT_FOUND` | 404 | Valid-format token has no photo record | Do not expose filesystem details |
| `PHOTO_DELETED` | 410 | Photo was deleted | Keep deletion result idempotent where existing behavior permits |
| `PRINT_UNAVAILABLE` | 503 | Printer protocol/device has not been verified or is unhealthy | Never report a successful print |
| `INTERNAL_ERROR` | 500 | Unexpected service error | Log correlation ID and sanitized stack details server-side |

现有路由的错误体是扁平结构 `{ "ok": false, "error": "<code>", "detail": "<detail>" }`（`Handler._error` 1243-1244），既有 code 包括 `consent_required`、`gone`、`not_found`、`unknown_job`、`internal`、`bad_url`、`invalid_style`、`consent_declined`；上表错误码与嵌套错误体只适用于本轮**新增**路由，既有路由的错误体与 code 不得改动。`POST /api/consent` 拒绝同意时现状返回 200 `consent_declined`，新增 purpose 必须保留该行为。

- Queue submission retry: clients may retry with the same `request_id`; the service must return the original entry if the normalized payload matches.
- AIGC retry: no automatic retry by default, to avoid duplicate billing. One retry may be enabled only after gateway idempotency and cost behavior are confirmed.
- Camera retry: one health recheck after a configurable delay is permitted. Repeated `STREAMON` or device reset loops are prohibited; the known failure is physical and requires operator intervention.
- Gesture: never convert low confidence, missing frames, multiple people, or out-of-frame observations into a positive trigger.
- L0 fallback: allowed only after a valid authorized capture exists. If capture itself fails, no pickup token or successful job may be issued.
- Delete: repeated deletion must not restore or regenerate the photo. Remove or invalidate image, thumbnail, QR cache, and related accessible copies according to the confirmed retention policy.

## Security
- Capture authorization continues to use the existing consent-token mechanism. `POST /api/capture` without a valid token must return `403`.
- External processing consent is separate from capture consent. No gateway request may occur without explicit external-processing consent for that job.
- Gateway request allowlist: source image and required style parameters only. Deny names, phone numbers, WeChat IDs, display numbers, queue IDs, photo tokens, QR images, and consent identifiers.
- The 22-character photo token is the only pickup authorization credential. Generate it using a cryptographically secure random source. Do not log it in ordinary access logs or state/overlay payloads.
- Display number `SM-YYYY-NNNN` is non-secret and must never authorize page, image, thumbnail, QR, deletion, or print access.
- Validate JSON content type, body size, field types, style IDs, token format, and configured optional-field allowlist. Reject unexpected fields where practical.
- Bind CSRF-sensitive state-changing requests to same-origin requests. Do not enable permissive cross-origin access.
- Escape participant-provided text before rendering. Do not place optional fields in public stage/overlay content.
- Keep gateway credentials in process environment or a protected local configuration source. Never include credentials in HTML, static JS, logs, test fixtures, or `style-catalog.json`.
- 授权现状（T-10 核实）：`/api/operator/*` 与 `/operator` 页面**没有任何鉴权**，任何能连到 8090 端口的人都能改 AIGC 目录、复位 USB、purge/reset（1310-1413）；仓库内无反向代理/隧道配置。实现要求：内部手势摄入与操作员/运维路由必须限制在回环或显式本地授权；在 T-20/T-19 完成前，不得把它们当作已受保护的接口。未确认项：K3 现场是否有仓库外的隧道/代理限制 `/api/*` 的来源——**未知**，默认按“无保护”处理。
- 同意绑定（T-10 核实现状）：`POST /api/consent` 签发 `uuid.uuid4().hex`（32 字符）令牌，仅存内存、默认 TTL 600s（`BOOTH_CONSENT_TTL`），`/api/capture` 从 `X-Booth-Session` 或 `consent_token` 校验，无主体/队列绑定（153-196、1355-1376）。新增实现必须先落地绑定校验（`capture_consent_id` ↔ 队列条目；`external_processing_consent_id` ↔ 作业）再接线生产。
- 已知缺陷（T-10 核实）：`GET /api/mask/<name>.png` 按连号记录编号提供掩码、无令牌校验（1338-1339、440、905-907）；在改为令牌寻址或仅回环前，生产不得依赖“掩码不可被枚举”这一假设。
- Store only necessary consent metadata. Define retention, deletion propagation, file permissions, and backup handling before production use.
- No face recognition, identity matching, clustering, or face database is permitted. Person segmentation is the only approved person-analysis category.

## Testing strategy
- **Unit**
  - Test queue transitions, capacity, deadline expiry, idempotency replay/conflict, and prohibited transitions using a fake clock and in-memory store.
  - Test token generation format, uniqueness across at least 100,000 generated test tokens, rejection of display-number format, and deleted-token behavior.
  - Test consent purpose isolation: capture consent cannot substitute for external-processing consent.
  - Test gateway request serializer with sentinel personal data; assert prohibited fields and values are absent.
  - Test L0 fallback for gateway error/timeout, and assert capture failure does not create a pickup token.
  - Test that disabled/unavailable gesture, multiple people, out-of-frame results, unstable frames, and low confidence never trigger capture.
  - Passing means deterministic tests pass without network, camera, AI-core, or printer hardware dependencies.
- **Integration**
  - Run `booth_server.py` with temporary storage and fake camera, gateway, gesture, and print adapters.
  - Verify HTTP status, JSON schemas, same-origin behavior, state transitions, queue notifications, deletion behavior, and existing route compatibility.
  - Verify `POST /api/capture` still returns `403` without a valid consent token.
  - Verify number-based pickup access returns `404`.
  - Verify external request capture contains only image/style fields after explicit external consent.
  - Passing means all routes meet this specification and no test writes to production data.
- **End-to-end**
  - Use browser automation or the existing repository E2E harness, without adding npm dependencies, to exercise entry carousel, optional-field omission, style submission, queue status, called/start UX, pickup QR, save, delete, and print-unavailable UX.
  - Use deterministic fake camera frames for software workflow tests. Hardware acceptance is a separate K3 test.
  - On K3, first verify the camera obtains actual frames. Current known hardware fault means this gate is presently **no-go**.
  - Gesture hardware gate requires documented model source/license, quantization, AI-core slot use, frame rate, latency, false-trigger and miss-rate results. Until passed, `gesture.enabled=false`.
  - Printer gate requires exact device model, protocol discovery, actual print acknowledgement, and failure behavior. Until passed, `printer.enabled=false`.
  - Passing means all software E2E tests pass; hardware-dependent claims are separately marked verified only with recorded device test evidence.
- **Fixtures**
  - Synthetic non-identifying test images only.
  - Temporary directories for image and state storage.
  - Fake clock, fake gateway responses, fake camera readiness, scripted gesture sequences, and fake printer outcomes.
  - No real participant details, real tokens, or production credentials in fixtures.

## Unknowns
- Existing repository route shapes, storage backend, page asset locations, consent-token schema, job schema, and service launch command **已核查**（T-10，2026-09-30；见 `docs/spec/仓库契约-v1.md`）。
- 兼容性现状（T-10 已核实）：现有错误体为扁平 `{ok,error,detail}`；`/api/state` 已有 `queue: 0` 占位；同意令牌全局无绑定；`python3 -m unittest discover` 实测不可用。新增路由/字段必须遵守这些约束。
- **未知（阻塞生产）**：K3 现场是否存在仓库外的反向代理/隧道限制 `/api/*` 或 `/api/operator/*` 的来源——仓库内无证据；在查明前按“无保护”处理，禁止把运营路由当作已受保护。`BOOTH_DATA` 现场实际内容（`settings.json`、records 数量）未在本任务读取，改动存储前需现场确认。
- OK gesture model source, license, hand-keypoint support, quantization, RISC-V/AI-core compatibility, runtime, slot allocation, 1080p latency, sustainable FPS, single-person detection strategy, confidence threshold, stable-frame count, and measured false-trigger/miss rates are unknown. Automatic triggering is no-go until verified on K3.
- Camera frame acquisition is currently **not working**. The confirmed physical chain fault requires cable, port, or power remediation and a new frame-acquisition test; software self-recovery is not an accepted fix.
- Queue maximum, event concurrency, fairness policy, duplicate identity rules, start deadline, grace period, notification channel, and behavior when a participant’s phone disconnects are not finalized.
- Optional participant fields, purpose, retention, access control, and whether they need to be stored are not finalized.
- External gateway data location, retention, training use, SLA, rate limits, idempotency, image limits, cost, and contractual terms are unknown. External processing must remain gated on separate notice and consent.
- L0 definition, output dimensions, file format, and user-facing fallback copy need product confirmation.
- Printer model, AirPrint/IPP support, vendor API, network reachability, app-only requirements, acknowledgement semantics, consumables, price, and measured throughput are unknown. No print size or throughput can be promised.
- Event date, expected participants, open hours, desired per-person image/print count, budget, staffing, network behavior, power recovery, and offline requirements are unknown.
- Photo retention duration and deletion propagation to original, styled output, thumbnail, QR cache, backups, and external provider copies are unresolved.
- Proposed performance budgets and default queue/countdown values are engineering targets, not measurements. K3 benchmarks and product approval are required before treating them as deployment commitments.
