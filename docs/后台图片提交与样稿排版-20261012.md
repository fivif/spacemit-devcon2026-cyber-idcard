# 后台图片提交与样稿排版

## 使用方式

K3：<http://192.0.2.10:8090/operator/photos>。Windows 当前演示服务：<http://127.0.0.1:8091/operator/photos>。

成片管理顶部的「直接提交图片」支持 JPG、PNG、WEBP，最大20 MB、2400万像素。可选填写姓名与账号。

- 「AIGC 风格」：选择已启用风格、横竖版及非Q版/Q版，使用既有生图流程。
- 「原图（不做 AIGC）」：不调用相机、人像分割或生图，保留原背景与衣服。带标识版按选定画幅裁排，无标识版保留上传图片尺寸及背景。
- 完成后在下方成片卡片下载或打印带标识版、无标识版。后台打印可重复；用户取图页仍只允许打印带标识版一次。

无标识原图会按现有存储方式保存为 JPEG，并不是上传文件的逐字节副本。没有进行真实出纸验收。

## 版式

以用户确认的1024×1536竖版样稿为依据：官方绿色Logo高38，左上位置(138,112)；大会标题31像素，与Logo间距15；姓名55像素，位于(166,1177)；账号27像素，位于(168,1254)。姓名账号过长时缩小字体，底部渐变和绿色签名线保留。没有副标题、标签或编号。

生成成功、生成失败保留原图、后台原图三个分支统一接收并保存文字层函数返回的新图，修复此前丢弃返回值造成Logo和信息缺失的问题。旧成片不会自动重绘。

随项目分发Noto Sans CJK Bold及许可证，Win/K3优先使用相同字体。两端对同一源图离线渲染，字体SHA256相同，Logo与中文姓名区域逐像素相同；英文边缘有1358个像素不同，占全图0.0863%，通道平均误差0.0609/255。不能称为两端逐像素完全相同。

## 后台 AIGC 连续失败修复

现场后台上传69、70、73、75、76、78、81号记录均在人像处理阶段超时，随后错误地显示“画面里没有检出人像”。这些任务没有真正进入AIGC生成。74号相机记录另为AIGC网络失败，77、79、80号相机记录生成成功。用户已删除的图片未恢复。

上传此前把模型准备、分割、MODNet抠像及回传共用10.5秒预算，也没有相机倒计时期间的模型预热。现改为独占切换人像模型，准备阶段最多30秒；处理副本等比缩至长边1920，分割与抠像单独至少20秒预算。保留原始上传文件，检测框与alpha映射回原图。原图模式继续跳过这些步骤，相机预算不改。

推理异常与真实无人分开处理：人像处理失败时保留原图，不调用生图、不误报无人；后台显示“人像处理未完成，已保留原图，请重试。”及“已保存原图”，不冒充生成成功。
