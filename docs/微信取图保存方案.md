# 微信取图保存方案

## 用户操作

微信扫码进入 `/p/<取图令牌>`，点击“保存带标识版”或“保存无标识版”，页面展开对应版本的真实图片。长按图片，选择微信系统菜单中的“保存图片”或“存储到照片”。页面不会宣称已经保存。

没有保存菜单时，点微信右上角“…”选择在浏览器打开，或点击“复制取图链接”后在 Safari / 系统浏览器打开。复制被拒时，会显示可长按复制的链接框。“打开完整图片”提供当前版本的同源图片地址，不加 download 属性。

其他浏览器仍使用原有直接下载；提供“无法下载？长按保存”作为人工兜底。没有无标识图片时，两个位置的无标识入口均隐藏；无标识图片加载失败不会展示上一版本或误报整张照片已删除。

## 实现

- `app/static/js/pick.js` 根据 MicroMessenger 标识选择微信保存流程。UA识别仅影响交互，不能作为授权检查。
- 保存面板使用普通 `<img>`，直接指向 `/api/photo/<令牌>.jpg` 或 `.clean.jpg`；不使用缩略图、canvas、截图、Blob URL 或 Base64 代替原文件。不屏蔽长按菜单。
- 图片接口仍返回 `image/jpeg`，不强制 attachment；现有公网 Nginx 白名单已包含两个图片版本及所需 HTML/CSS/JS，无需新增公开设备接口。
- 同源网页无法强制写入微信相册或得知用户是否保存成功。微信公众号 JSSDK 的图片预览也不等于静默保存授权，本方案不依赖公众号签名或新增服务。
- 链接被微信整体封禁、域名或有效HTTPS证书未部署、隧道断开属于独立问题；页面保存流程不能绕过这些限制。
- 原有照片权限、下载两版本和仅带标识版单次打印规则不变。

## 验证

运行 `app/tests/test_pick_save_frontend.js`，使用已安装Chrome和Playwright依赖。54项覆盖 iPhone/Android 微信UA、长按图片版本切换、失败不展示旧图、复制拒绝兜底、收起焦点/键盘、删除状态收起、无横向溢出、无标识缺失及普通浏览器两版真实下载字节。

上述为桌面Chrome模拟微信标识，不是微信真机。现场仍需分别在iOS和Android微信扫码，长按保存两版本，打开系统相册检查图片清晰度、标识版本和人物内容，并确认“在浏览器打开”的路径可用。无需重新拍摄，使用已有照片即可。
