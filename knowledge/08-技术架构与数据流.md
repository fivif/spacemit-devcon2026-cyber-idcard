## 🔌 进程模型与 IPC

### 主进程（booth_server.py）

```
Flask HTTP 服务器 (0.0.0.0:8090)
├── 主线程：HTTP 请求处理
├── preview_thread：MJPEG 流发送（camera.subscribe）
├── gesture_preview_thread：手势检测（1.5s 间隔）
└── PresenceSensor._loop 线程：在场检测（1.2s 间隔）
```

### 子进程 1：infer/worker.py

```
启动方式：subprocess.Popen([python, "infer/worker.py"])
通信协议：stdin/stdout 行式 JSON（@@J 前缀）
运行时：spacemit_ort（SpaceMIT EP，AI 核 8 槽）
不能同时用：cv2（会冲突）

请求格式：
{"id": 1, "op": "seg", "image": "/path/to/image.jpg", "prompts": ["person"], "conf": 0.20}

响应格式：
@@J {"ok": true, "persons": [...], "time_ms": 123.4, "id": 1}

支持的操作：
- health：探活（返回 EP 可用性）
- seg：YOLOE 分割（prompts=["person"/"face"/...])
- det：YOLOv8 检测（❌ 在 K3 上超时，已弃用）
- matte：MODNet 抠像（返回 alpha 通道）
```

### 子进程 2：gesture/worker.py

```
启动方式：subprocess.Popen([python, "gesture/worker.py"])
通信协议：stdin/stdout 行式 JSON（@@J 前缀）
运行时：cv2 + onnxruntime（CPU-only，不能用 spacemit_ort）
模型：palm.onnx (192×192) + handpose.onnx (224×224)

请求格式：
{"id": 1, "op": "ok", "image": "/path/to/image.jpg", "person_boxes": [[x1,y1,x2,y2]]}

响应格式：
@@J {"ok": true, "is_ok": false, "ok_boxes": [], "persons": 1, "engine": "handpose"}

支持的操作：
- ok：检测 OK 手势或竖大拇指（取决于 BOOTH_GESTURE_TYPE）
- health：探活
```

### 为什么是子进程而不是线程？

1. **cv2 和 spacemit_ort 冲突**：两者都初始化 ONNX Runtime，会抢 ORT 日志管理器，导致段错误
2. **AI 核独占**：SpaceMIT EP 需要独占访问，子进程隔离更安全
3. **崩溃隔离**：worker 崩溃不会拖垮主服务，客户端自动重启

### 为什么用行式 JSON 而不是 msgpack / protobuf？

1. **调试友好**：可以直接 `tail -f` 看通信内容
2. **无依赖**：不需要额外安装 msgpack / protobuf
3. **EP 噪声问题**：EP 启动时会往 stdout 打 48 行非 UTF-8 噪声，二进制协议会彻底打碎，JSON 可以用 `@@J ` 前缀跳过

## 🔐 安全模型

### 1. 令牌设计

```python
token = secrets.token_urlsafe(16)  # 128 位随机，22 字符
# 示例：V3f2O3CT2bl_Yt8hov2LLQ
```

**为什么不用编号**：
- 编号是连号的（`0001`、`0002`、...），可以枚举
- 128 位随机令牌的暴力破解概率 < 2^-128

### 2. 访问控制

| 路径 | 凭证 | 权限 |
|---|---|---|
| `/api/photo/<令牌>.jpg` | 令牌（URL） | 查看成片 |
| `/api/thumb/<令牌>.jpg` | 令牌 | 查看缩略图 |
| `/api/qr/<令牌>.png` | 令牌 | 查看二维码 |
| `/api/photo-meta/<令牌>.json` | 令牌 | 查看元信息（**不返回令牌**） |
| `DELETE /api/photo/<令牌>` | 令牌 | 删除照片 |

**编号不能用来访问任何资源**：
```python
# store.py:by_token()
def by_token(token: str) -> Record | None:
    path = self.data_dir / f"photo-{token}.jpg"
    if not path.exists():
        return None  # 404
    # ...
```

### 3. 数据留存

```python
# 默认 7 天（168 小时）
retention_hours = int(os.environ.get("BOOTH_RETENTION_HOURS", "168"))

# 自动清理（需手动触发或定时任务）
store.purge(max_age_hours=retention_hours)
```

**合规要求**："留存 7 天" 目前需要人工触发，无自动定时清理（见 `05-资产现状.md` 技术债 #5）。

## 🐛 常见问题与排查

### 问题 1：seg 超时（当前阻塞）

**现象**：`journalctl` 显示 "seg 超时（8.0s）"

**排查步骤**：
1. 检查 infer worker 是否在运行：`ps aux | grep infer/worker.py`
2. 检查 EP 可用性：`curl http://localhost:8090/api/state | jq .infer_stats.ep`
3. 检查是否有多个线程同时调用 seg：
   - presence 线程（1.2s 间隔）
   - gesture 线程（1.5s 间隔）
4. 查看 worker 日志：`journalctl -u devcon-booth.service | grep "call(seg)"`

### 问题 2：手势检测 available=False

**现象**：`/api/state` 的 `gesture_obs.available` 始终是 `False`

**原因**：`_person_boxes_for()` 返回 `None`（seg 超时或没检测到人）

**排查步骤**：
1. 查看 gesture_obs：`curl http://localhost:8090/api/state | jq .gesture_obs`
2. 确认是否因为 seg 超时：`journalctl -u devcon-booth.service | grep "手势验真"`
3. 临时方案：注释掉 `gesture_client.py:365-376` 的人形框检查

### 问题 3：相机黑屏

**现象**：`/api/preview.mjpg` 无画面

**排查步骤**：
1. 检查设备是否存在：`ls -l /dev/video0`
2. 检查设备是否被占用：`lsof /dev/video0`
3. 检查相机状态：`curl http://localhost:8090/api/state | jq .camera`
4. 测试 v4l2 直接读取：`v4l2-ctl --device=/dev/video0 --all`

### 问题 4：infer worker 连续重启

**现象**：日志显示 "推理 worker 连续重启超过 5 次"

**原因**：
1. 模型文件缺失或损坏
2. EP 驱动异常
3. 内存不足
4. Python 路径错误（必须用 `/usr/bin/python3`）

**排查步骤**：
1. 手动启动 worker 看错误：`/usr/bin/python3 /opt/devcon/app/infer/worker.py`
2. 检查模型文件：`ls -lh /opt/devcon/assets/models/`
3. 检查内存：`free -h`
