## 🚀 部署流程

### 方法 1：单文件部署（推荐，快速修改）

```bash
# 从开发机上传单个文件
cd '~/devcon2026\app'
scp booth_server.py root@192.0.2.10:/opt/devcon/app/

# 上传子目录文件
scp infer_client.py root@192.0.2.10:/opt/devcon/app/
scp presence.py root@192.0.2.10:/opt/devcon/app/
scp gesture/worker.py root@192.0.2.10:/opt/devcon/app/gesture/
scp infer/worker.py root@192.0.2.10:/opt/devcon/app/infer/

# 重启服务
ssh root@192.0.2.10 "systemctl restart devcon-booth.service"

# 查看日志（确认启动成功）
ssh root@192.0.2.10 "journalctl -u devcon-booth.service --since '10 seconds ago' --no-pager"
```

### 方法 2：整个 app 目录同步（全量更新）

```bash
# 同步整个目录（排除 data/ 和 __pycache__）
cd '~/devcon2026'
rsync -avz --exclude='data/' --exclude='__pycache__/' --exclude='*.pyc' \
    app/ root@192.0.2.10:/opt/devcon/app/

# 或者用 scp -r（Windows 上更可靠）
scp -r app/* root@192.0.2.10:/opt/devcon/app/

# 重启服务
ssh root@192.0.2.10 "systemctl restart devcon-booth.service"
```

### 方法 3：使用 deploy.py（自动化脚本，但只部署 booth_server.py）

```bash
cd '~/devcon2026\app'
python deploy/deploy.py --host 192.0.2.10 --restart

# ⚠️ 注意：deploy.py 只上传 booth_server.py，其他文件需手动 scp
```

### 方法 4：Git 拉取（如果代码已推到远程仓库）

```bash
# 在 K3 上直接 pull
ssh root@192.0.2.10
cd /opt/devcon/app
git pull origin main
systemctl restart devcon-booth.service
```

## ⚙️ systemd 服务管理

### 服务文件位置

```
主配置：/etc/systemd/system/devcon-booth.service
配置覆盖：/etc/systemd/system/devcon-booth.service.d/
├── gesture-handpose.conf    ← 手势引擎配置（当前启用）
└── （其他 .conf 文件按字母序加载）
```

### 主服务文件内容

```ini
# /etc/systemd/system/devcon-booth.service
[Unit]
Description=DevCon 2026 Photo Booth
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/opt/devcon/app
ExecStart=/usr/bin/python3 /opt/devcon/app/booth_server.py
Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

### 常用命令

```bash
# 启动服务
systemctl start devcon-booth.service

# 停止服务
systemctl stop devcon-booth.service

# 重启服务（最常用）
systemctl restart devcon-booth.service

# 查看状态
systemctl status devcon-booth.service

# 开机自启
systemctl enable devcon-booth.service

# 取消自启
systemctl disable devcon-booth.service

# 重载 systemd 配置（修改 .service 文件后必须执行）
systemctl daemon-reload
```

### 修改环境变量（推荐方式）

```bash
# 创建或编辑 drop-in 配置文件
ssh root@192.0.2.10
mkdir -p /etc/systemd/system/devcon-booth.service.d
nano /etc/systemd/system/devcon-booth.service.d/my-config.conf

# 添加环境变量
[Service]
Environment="BOOTH_GESTURE_ENABLED=true"
Environment="BOOTH_GESTURE_ENGINE=handpose"
Environment="BOOTH_PRESENCE_INTERVAL=3.0"

# 保存后重载并重启
systemctl daemon-reload
systemctl restart devcon-booth.service
```

### 查看生效的环境变量

```bash
# 查看服务的完整环境变量
systemctl show devcon-booth.service | grep Environment

# 或者从进程里看
ps aux | grep booth_server.py
cat /proc/<PID>/environ | tr '\0' '\n' | grep BOOTH_
```

```bash
journalctl -u devcon-booth.service -f | grep -E "超时|timeout|重启|restart"
```

### 日志级别

```python
# booth_server.py 的日志级别默认是 INFO
import logging
logging.basicConfig(level=logging.INFO)

# 临时改成 DEBUG（看更详细的日志）
logging.basicConfig(level=logging.DEBUG)
```

### 常见日志模式

| 日志内容 | 含义 | 行动 |
|---|---|---|
| `服务就绪于 http://...` | 启动成功 | ✅ 正常 |
| `worker 就绪，EP 可用` | 推理 worker 启动成功，AI 核可用 | ✅ 正常 |
| `worker 就绪，EP **不**可用` | 推理 worker 降级到 CPU | ⚠️ 性能下降 |
| `seg 超时（8.0s）` | 分割模型超时 | ❌ 当前阻塞问题 |
| `推理 worker 连续重启超过 5 次` | worker 崩溃 | ❌ 检查模型/内存 |
| `手势验真取人形框失败` | seg 超时或没检测到人 | ⚠️ 手势不可用 |
| `camera 不可用` | 相机设备打不开 | ❌ 检查 /dev/video0 |
| `call(seg) finally: clearing _busy` | 推理调用完成（debug 日志） | ℹ️ 待清理 |

## 🐛 常见问题排查

### 问题 1：服务启动失败

**症状**：`systemctl status devcon-booth.service` 显示 `failed`

**排查步骤**：
1. 查看详细错误：`journalctl -u devcon-booth.service -n 50`
2. 检查 Python 路径：`which python3`（必须是 `/usr/bin/python3`）
3. 检查工作目录：`ls -la /opt/devcon/app/booth_server.py`
4. 检查权限：`ls -l /opt/devcon/app/booth_server.py`
5. 手动启动看错误：`cd /opt/devcon/app && /usr/bin/python3 booth_server.py`

**常见原因**：
- Python 路径错误（用了 venv 的 python）
- booth_server.py 不存在或权限不对
- 缺少依赖（numpy / PIL / cv2 / onnxruntime）

### 问题 2：端口被占用

**症状**：日志显示 `Address already in use`

**排查步骤**：
1. 查看谁占用了 8090：`ss -tlnp | grep 8090`
2. 杀掉占用进程：`kill <PID>`
3. 或者换个端口：修改 `devcon-booth.service` 的 `ExecStart` 加 `--port 8091`

### 问题 3：相机不可用

**症状**：`/api/state` 的 `camera.ok` 是 `false`

**排查步骤**：
1. 检查设备：`ls -l /dev/video0`
2. 检查占用：`lsof /dev/video0`
3. 检查权限：`ls -l /dev/video0`（应该是 `crw-rw----+ 1 root video`）
4. 测试直接读取：
   ```bash
   v4l2-ctl --device=/dev/video0 --set-fmt-video=width=1920,height=1080,pixelformat=MJPG
   v4l2-ctl --device=/dev/video0 --stream-mmap --stream-count=1
   ```

**常见原因**：
- 设备不存在（USB 相机没插）
- 设备被其他进程占用（如之前的 booth 进程没杀干净）
- 格式不支持（用了 `MJPG` 但相机只支持 `JPEG`）

### 问题 4：EP 不可用（AI 核降级到 CPU）

**症状**：日志显示 `worker 就绪，EP **不**可用`，`/api/state` 的 `infer_stats.ep` 是 `false`

**排查步骤**：
1. 检查驱动：`lsmod | grep spacemit`
2. 检查设备节点：`ls -l /dev/spacemit*`
3. 测试 EP：
   ```bash
   cd /opt/devcon/app
   /usr/bin/python3 -c "import spacemit_ort; print(spacemit_ort.get_available_providers())"
   ```

**常见原因**：
- EP 驱动未加载（系统更新后可能丢失）
- spacemit_ort 未安装或版本不对
- 其他进程占用了 EP（AI 核只能单进程独占）

### 问题 5：seg 超时（当前阻塞问题）

**症状**：日志显示 `seg 超时（8.0s）`，手势检测 `available=false`

**排查步骤**：
1. 确认是否真的超时：`journalctl -u devcon-booth.service | grep -E "seg|超时"`
2. 查看 infer worker 状态：`ps aux | grep infer/worker.py`
3. 查看是否有多个线程同时调用 seg：
   ```bash
   journalctl -u devcon-booth.service -n 200 | grep "call(seg)" | tail -20
   ```
4. 尝试手动调用 seg 看耗时：
   ```bash
   cd /opt/devcon/app
   echo '{"id": 1, "op": "seg", "image": "data/presence-frame.jpg", "prompts": ["person"], "conf": 0.15, "mask": false, "matte": false}' | /usr/bin/python3 infer/worker.py
   ```

**临时解决方案**（见 `07-新接手者必读.md`）：
- 注释掉 `gesture_client.py:365-376` 的人形框检查
- 调高 `BOOTH_GESTURE_HAND_CONF` 到 0.5+

### 问题 6：手势不触发

**症状**：做了手势但没反应

**排查步骤**：
1. 确认手势引擎已启用：`systemctl show devcon-booth.service | grep BOOTH_GESTURE_ENABLED`
2. 查看 gesture_obs：`curl http://localhost:8090/api/state | python3 -m json.tool | grep -A 10 gesture_obs`
3. 查看 available 字段：如果是 `false`，说明人形框获取失败（seg 超时）
4. 查看 is_ok 字段：如果是 `false`，说明检测到手但不是目标手势
5. 查看日志：`journalctl -u devcon-booth.service -f | grep gesture`

**常见原因**：
- `BOOTH_GESTURE_ENABLED` 没设为 `true`
- seg 超时导致 `available=false`
- 手势类型配置错误（做的是 OK 手势，但配置的是 `thumbs_up`）
- 置信度门槛太高（`BOOTH_GESTURE_HAND_CONF` 太高）

## 🔧 配置调优

### 降低 CPU 占用（降低检测频率）

```ini
# /etc/systemd/system/devcon-booth.service.d/perf-tuning.conf
[Service]
Environment="BOOTH_GESTURE_PROBE_INTERVAL=3.0"    # 从 1.5s 改到 3s
Environment="BOOTH_PRESENCE_INTERVAL=5.0"         # 从 1.2s 改到 5s
```

### 提高手势灵敏度（降低置信度门槛）

```ini
[Service]
Environment="BOOTH_GESTURE_HAND_CONF=0.20"        # 从 0.30 降到 0.20
Environment="BOOTH_GESTURE_STABLE_FRAMES=2"       # 从 3 降到 2（连续 2 帧即可）
```

### 提高手势准确性（提高置信度门槛）

```ini
[Service]
Environment="BOOTH_GESTURE_HAND_CONF=0.50"        # 从 0.30 升到 0.50
Environment="BOOTH_GESTURE_STABLE_FRAMES=5"       # 从 3 升到 5（连续 5 帧才触发）
```

### 切换手势类型

```ini
[Service]
# 竖大拇指（当前）
Environment="BOOTH_GESTURE_TYPE=thumbs_up"

# 或者 OK 手势
Environment="BOOTH_GESTURE_TYPE=ok"
```

### 延长照片留存期

```ini
[Service]
Environment="BOOTH_RETENTION_HOURS=336"           # 从 7 天改到 14 天
```

## 🆘 紧急恢复

### 服务完全卡死（无响应）

```bash
# 强制杀掉所有相关进程
ssh root@192.0.2.10 "pkill -9 -f booth_server.py"
ssh root@192.0.2.10 "pkill -9 -f 'infer/worker.py'"
ssh root@192.0.2.10 "pkill -9 -f 'gesture/worker.py'"

# 重启服务
ssh root@192.0.2.10 "systemctl restart devcon-booth.service"
```

### 相机设备卡死

```bash
# 重新加载 v4l2 驱动
ssh root@192.0.2.10 "modprobe -r uvcvideo && modprobe uvcvideo"

# 或者重启系统（最后手段）
ssh root@192.0.2.10 "reboot"
```

```bash
# 重新加载 EP 驱动
ssh root@192.0.2.10 "modprobe -r spacemit_ep && modprobe spacemit_ep"

# 重启服务
ssh root@192.0.2.10 "systemctl restart devcon-booth.service"
```

### 恢复到出厂状态

```bash
# 清空所有数据（照片 / 计数器 / 配置）
ssh root@192.0.2.10 "rm -rf /opt/devcon/app/data/*"

# 重启服务
ssh root@192.0.2.10 "systemctl restart devcon-booth.service"
```
